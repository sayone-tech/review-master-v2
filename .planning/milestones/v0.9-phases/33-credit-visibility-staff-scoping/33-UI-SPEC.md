# Phase 33 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope (Org Admin + Staff surfaces; the same components, no role branching, D-10):**
1. "AI Reply Credits" card at the top of Shop Details (CVIS-01, D-09..D-12)
2. Credits badge column on every Shops-list row (CVIS-02, D-01..D-04)
3. Reply composer: credits line, "Generate with AI (requires N credits)" button, per-tone cost, disabled states, 402 handling (CVIS-03, D-05..D-08)
4. Buy More Credits modal, opened from surfaces 1 and 3 (the badge reaches it via the card, D-01) (CVIS-04, D-13..D-16)
5. Activity Log: presentation of credit events for Org Admin (CVIS-05) — type pill, action labels, and the shop name on shop-entity credit rows (user-confirmed)
6. Staff Shops-list empty state, a consequence of `list_shops` Staff scoping (SCOPE-01)

**Sources:** locked decisions D-01..D-16 from `33-CONTEXT.md` (not re-asked); backend contract from `30-CONTEXT.md` D-08..D-12; spec `Requirements_Credits_System.md` §5.2/§9.1/§9.2/§9.4/§9.5; tokens, shells and number/date conventions from the sibling `32-UI-SPEC.md`; existing code read this session: `frontend/src/widgets/{shop-management,review-management,modal,audit-log,data-table}/*`, `frontend/tailwind.config.js`, `frontend/src/styles/tailwind.css`, `templates/shops/shop_list.html`, `frontend/src/entrypoints/shop-management.tsx`. Everything not marked "default" is taken from one of those.

**Nothing new is introduced** except: one display size (24px, the card's big number) and one dark-green text colour (`#166534`, AA text on `green-tint`) — both named and justified below. No new icon library, font, radius or dependency.

## Spacing Scale

Declared values (multiples of 4) used by every NEW element in this phase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge vertical padding (`py-1`), caption-to-number gap, icon gaps (`gap-1`), line-to-link gap |
| sm | 8px | Badge horizontal padding (`px-2`), gap between card rows (`gap-2`), bar-to-footer-line margin (`mt-2`), gap between tone-pill text and cost, composer line bottom margin (`mb-2`) |
| md | 16px | Card padding (`p-4`), Buy More icon-to-text gap (`gap-4`), card-internal section gap (`mt-4`), standalone-button horizontal padding (`px-4`) |
| lg | 24px | Gap between the credits card and the details `dl` (`mb-6`, matches the `dl`'s own `gap-x-6`), Modal shell padding (shell-owned `px-6`) |
| xl | 32px | Standalone in-card / in-composer button and link height (`h-8`), skeleton block heights use multiples of 4 |
| 2xl | 48px | Buy More icon tile (`w-12 h-12`, `rounded-confirm-icon`) |
| 3xl | 64px | not used |

Control heights: standalone buttons/links added by this phase (`Buy More Credits`, `Retry`) are `h-8` (32px). Progress bar `h-2` (8px). The badge is not height-set; 12px text at line-height 1.5 plus `py-1` = 26px.

Exceptions (exhaustive):
1. **32px (`h-8`) standalone controls and the 26px badge are below the 44px mobile target.** Rationale: all exceed the WCAG 2.2 SC 2.5.8 minimum of 24x24 CSS px; the badge sits in a 48px-tall table row and the link/buttons are secondary actions. 44px is not enforced (same exception as Phase 32).
2. Shared shell internals stay untouched and are not specified here (`Modal` `px-6 pt-[22px]` header, footer `py-4`).
3. Existing composer controls keep their shipped sizes (`px-2 py-1` pills/buttons, `px-4 py-2` Discard/Submit); only their text and states change.

### Band helper (D-03) — one function, shared by badge, bar and card text

`creditBand(remaining, total) -> "not_enabled" | "empty" | "green" | "amber" | "red"`. Integer maths, no floats:

| Condition (evaluate in order) | Band |
|-------------------------------|------|
| `total === 0` | `not_enabled` (never divide) |
| `remaining <= 0` | `empty` |
| `remaining * 100 > total * 25` | `green` |
| `remaining * 100 >= total * 5` | `amber` (25% and 5% exactly are amber) |
| otherwise | `red` |

`total = allocated + bonus` (never `allocated` alone). `remaining` is clamped to `>= 0` for display and band.

## Interaction Contract

### A. Shop Details credits card

- Placement: first child of the `Modal` body, above the existing `dl`; container `bg-line-soft rounded-md p-4 mb-6`. `data-testid="credits-card"`.
- Layout (top to bottom): header row (`Coins` 16px `text-muted` aria-hidden + `h3` title, period label right-aligned) -> big number row (`mt-4`) -> bar (`mt-2`) -> used/available line (`mt-2`) -> breakdown line -> footer row (`mt-4`, `flex items-center justify-between gap-2 flex-wrap`): renews line left, `Buy More Credits` button right (`h-8 px-4 text-[14px] font-normal`, secondary white).
- Progress bar: track `h-2 rounded-full bg-line`, fill `h-2 rounded-full` coloured by band (`green`/`amber`/`red`/`muted`), width = `remaining / total` (user-confirmed: the bar drains as credits are used, so it matches the big number; the 75%/95% "used" thresholds in spec §9.1 are the same boundaries as the remaining bands, D-03). `role="progressbar"`, `aria-valuemin=0`, `aria-valuemax={total}`, `aria-valuenow={remaining}`, `aria-valuetext="{remaining} of {total} credits remaining"`, `aria-label="AI reply credits remaining"`. No transition/animation. Not rendered when `total === 0` (no divide-by-zero).
- Data: fetch the shop credits endpoint on **every modal open** (D-11, endpoint is `no-store`); no polling, no refetch while open except the Retry button. Abort the request on close and ignore stale responses (shop switched mid-flight). The result is written to the balance store (below) so the Shops-list badge for that shop agrees with the card.
- States: loading (skeleton: title row real, then three `animate-sk-pulse bg-line rounded-sm` blocks `h-8 w-24`, `h-2 w-full`, `h-4 w-48`, `aria-busy="true"`); error (red-tint banner `bg-red-tint text-[#991B1B] rounded-md px-4 py-2 text-[12px] role="alert"` with heading, body and `Retry`; the rest of Shop Details stays fully usable); not enabled; populated bands. A shop with no row yet this month shows its full allocation (virtual balance) — rendered identically to any populated state.
- Opened from the badge (D-01): same modal, same component. `ShopModals` handles a new `shop:open-credits` window event (detail = the row, same shape as `shop:open-details`) by opening Shop Details with `focusCredits=true`. After mount, move focus to the card `h3` (`tabIndex={-1}`) in a deferred tick (`requestAnimationFrame`/`setTimeout 0`) so it runs after `FocusTrap` activation (which otherwise focuses the first tabbable, the X). Reset the flag when the modal closes. When opened any other way, focus follows the shell default.
- Buy More: opens `BuyMoreCreditsModal` with shop context. **Render it as a sibling of the Shop Details `Modal`, not inside its children.** While it is open, pass `dismissible={false}` to the Shop Details `Modal`: both `Modal`s register a document-level Escape listener, so without this one Esc press closes both. Closing Buy More returns focus to the `Buy More Credits` button (FocusTrap default).

### B. Shops-list badge column

- New column in `columns` between `status` and `created`: `key: "credits"`, `label: "CREDITS"`, `skeletonWidth: "72px"`. Rendered inside the existing `DataTable` (inherits its loading skeleton, empty and error states).
- Badge element: `<button type="button">` (it is interactive, D-01) `inline-flex items-center rounded-full px-2 py-1 text-[12px] font-semibold whitespace-nowrap` + band classes from Color; focus ring `focus-visible:outline focus-visible:outline-2 focus-visible:outline-ink`. `title` and `aria-label` per Copywriting. `data-testid="credits-badge-{row.id}"`.
- Click: `window.dispatchEvent(new CustomEvent("shop:open-credits", { detail: row }))`. Does NOT open Buy More directly (D-01; roadmap SC4's "from the Shops-list badge" is satisfied badge -> card -> Buy More).
- Source of numbers: row fields from `list_shops(with_credits=True)` (`None` when not requested). If the balance store has an entry for the shop (written by an opened card), the store wins over the row. When a row is replaced by an edit/activate/deactivate/create response that lacks credit fields, **preserve the previously known credit values** rather than blanking the badge; a row that has never had credits shows `—`.
- Search/filters/pagination are unchanged. No sorting by credits in this phase.
- Staff: the list contains only in-scope shops (SCOPE-01); the column is identical for Staff and Org Admin.

### C. Reply composer

Applies to every `ReplyComposer` whose review has a comment (`row.comment.trim() !== ""`). The shop is `row.shop_id`.

- **Star-only review** (blank comment): the AI button is not rendered (existing tone panel never opens); no credits line, no cost request, no Buy More link. (User-confirmed: the line is tied to generation, so it disappears with the button.)
- **Cost fetch:** on composer mount, `GET /api/v1/reviews/{id}/credit-cost/` -> `{cost, remaining, is_enabled}`. Cost always from the server; never computed on the client. `remaining`/`is_enabled` are written to the balance store keyed by `shop_id`; `cost` stays local to the composer (cost differs per review). Abort on unmount.
- **Layout (revised 2026-11-12, user request):** the status line sits directly under the `Generate with AI` button, right-aligned in the `YOUR REPLY` header row (button row and status line stack in a right-hand column): `<p id="credit-status-{row.id}" role="status" aria-live="polite">`, `text-[12px] text-muted text-right`. The insufficient state renders as a small amber callout (`bg-amber-tint border border-amber/30 rounded-md px-2.5 py-1.5`, `text-[#92400E]`, `AlertCircle` icon, `aria-hidden`). It shows the enabled/loading/disabled copy (one message at a time; the disabled messages replace the "This shop has..." line).
- **State machine** (button + line):

| State | Trigger | AI button | Line | Beneath composer |
|-------|---------|-----------|------|------------------|
| loading | cost request in flight | `disabled`, `aria-busy`, label `Generate with AI` | `Checking credits…` | — |
| ready | `is_enabled` and `remaining >= cost` | enabled, label `Generate with AI (requires {cost} credits)` | `{remaining} of {total} credits left this month` (SHOP-23; fallback `This shop has {remaining} credits remaining this month.`) (`text-muted`) | — |
| not enabled | `is_enabled === false` (cost response or 402 `reason: not_enabled`) | `disabled`, label `Generate with AI` | `AI replies aren't enabled for this shop.` (`text-muted`) | nothing (no Buy More link here, D-07) |
| insufficient | `is_enabled` and `remaining < cost` (cost response, post-generate, or 402 `reason: exhausted`) | `disabled`, label with cost | `Not enough credits — this reply needs {cost}, you have {remaining}.` (`text-[#92400E]`) | `Buy More Credits` link |
| load error | cost request failed | enabled (fail open), label `Generate with AI`, no cost suffix | `Couldn't check your credit balance.` + `Retry Credit Check` text button | — (the server still enforces; 402 below handles it) |

- **Disabled button style:** `disabled:bg-line-soft disabled:text-subtle disabled:cursor-not-allowed` (gray, per spec §5.3); native `disabled`, plus `aria-describedby="credit-status-{row.id}"` so the reason is announced. Inline text is the primary explanation (never tooltip-only, D-07); do not add a `title` that differs from the line.
- **Buy More link:** below the textarea/counter, on the same row as Discard/Submit, left-aligned (`flex items-center justify-between`; right side keeps the existing buttons): `inline-flex h-8 items-center text-[12px] font-semibold text-ink underline underline-offset-2 hover:text-muted`, `type="button"`, opens `BuyMoreCreditsModal` with shop context (`row.shop_name`, remaining, total unknown -> pass remaining only; total from the store if known). Only rendered in the insufficient state.
- **Tone pills (D-06):** the panel and pills keep their current structure. While `generatingTone !== null` ALL pills are `disabled` (already true; retained). With no draft the pills read `Professional` / `Friendly` (cost already shown on the button). Once a draft exists (`comment.trim() !== ""`, the "Replace your draft with AI reply?" mode) each pill shows `Professional · {N} cr` / `Friendly · {N} cr` and the `aria-label` carries the spelled-out cost. No additional confirm step.
- **After a successful generate:** write `credits_remaining` to the store (line updates immediately). If `remaining < cost` now, transition to *insufficient*. Existing focus behaviour (focus the textarea) is unchanged.
- **Credit fields on non-200 bodies:** 422 (output moderation: charged) and 422/502 (not charged) bodies carry `credits_charged` + `credits_remaining`; update the store from them, then show the existing error banner unchanged.
- **402 (D-08):** add a branch in `api.ts` that throws `ApiError` with `status 402` and the parsed body (`{code: "insufficient_credits", reason, required, remaining}`). In `handleGenerate`: close the tone panel, clear `generatingTone`, update the store (`remaining`; `is_enabled=false` for `not_enabled`; cost := `required` for `exhausted`), switch to *not enabled* / *insufficient* using the body numbers (not stale local numbers), show **no** generic error banner or toast, **keep the textarea content untouched**, and move focus to the textarea (the AI button is now disabled, so refocusing it would drop focus to `body`). The status line announces the change (`aria-live`).

### F. Cross-cutting rules

- **Balance store** (`creditsStore`): module-level, keyed by `shop_id`, holds `{ remaining, total?, isEnabled, periodLabel? }`, with subscribe so the badge, card and composer re-render. Written by: card fetch, composer cost fetch, every generate response (200/402/422/502). Never written from a 5xx with no credit fields.
- **Fail-open on cost-fetch failure (user-confirmed):** because the server is the authority and returns 402 on a real shortfall, a failed cost request leaves the button enabled (label without cost) and shows the Retry line. The 402 branch recovers the state.
- **No toasts** for any credit state; toasts remain only for pre-existing composer outcomes ("Reply posted.").
- **Dates:** UTC only (`timeZone: "UTC"`), `en-GB`; never `toLocaleDateString(undefined, …)` for credit dates (the existing `ShopDetailsModal.formatDate` uses the browser locale/zone and must NOT be reused for `renews_on`).
- **Keyboard / a11y:** every new control is a native `button`/`a`, reachable by Tab in DOM order; status lines are `role="status" aria-live="polite"`, error banners `role="alert"`; decorative icons `aria-hidden="true"`; no motion beyond the existing spinner and skeleton pulse (so `prefers-reduced-motion` needs no special handling).
- **Staff / Org Admin parity:** no role conditionals in the card, badge, composer or modal (D-10). Superadmin credit controls are Phase 32 and absent here (no "Allocate Bonus Credits" button on the card).
