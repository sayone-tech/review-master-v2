<objective>
Lead with SCOPE-01 end to end on the Shops API: a Staff GET /api/v1/shops/ -> ShopViewSet.list -> list_shops(user=..., with_credits=True) -> restrict_to_staff_scope (role-keyed StaffAccessScope filter) -> annotate_credit_state (one LEFT JOIN, never writes) -> ShopReadSerializer credit fields -> JSON rows with only in-scope shops and their virtual credit balance. Then harden the scope (empty scope, region scope, foreign-org region, cross-org), Staff-scope retrieve (D-17), add the single shared access selector the credits GET (Plan 33-04) uses, pin the fixed query count, and bootstrap the organisation name and support email on the Shops page for the Buy More modal.

Purpose: SCOPE-01 requires the Shops list and every credit endpoint to return only in-scope shops for Staff; CVIS-02 needs credits on every Shops-list row with a fixed query count. One Staff rule (restrict_to_staff_scope) serves list, retrieve and the credits GET so they cannot drift.

Output: apps/shops/selectors/shops.py (restrict_to_staff_scope, widened list_shops, get_accessible_shop_for_credits), ShopReadSerializer credit fields, ShopViewSet.get_queryset + list wiring, shop_list credits + credit_contact bootstrap, and tests.

Decisions implemented here: D-17 (retrieve is Staff-scoped, 404 out of scope), D-18 (Shops page stays Org-Admin-only; decorator and sidebar untouched), D-13/D-14/D-15 (support email and organisation name reach the page so the Buy More mailto can name the org), data for D-02/D-03/D-04 (badge numbers: remaining and total = allocated + bonus). Carried forward: SCOPE-01 research option (b) — a deliberate behaviour change (Staff, including JWT mobile clients, stop seeing out-of-scope shops); list_shops(with_credits=True) as one annotation with serializer fields defaulting to None (ROADMAP notes).

Claude's discretion recorded: the shared selector get_accessible_shop_for_credits lives in apps/shops/selectors/shops.py (not apps/credits) because apps/credits must never import apps.reviews (Phase 30 dependency rule, enforced by an invariant grep) and the Staff scope expansion lives in apps.reviews.selectors.reviews; it is implemented on top of list_shops so it shares the exact Staff rule. Flat credit fields (credits_remaining, credits_total, credits_allocated, credits_bonus) rather than a nested object (research A5). The bootstrap uses one dedicated json_script id, credit-contact, shared with the Reviews page (Plan 33-05).
</objective>
