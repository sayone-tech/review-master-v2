<objective>
Make the ledger tamper-resistant and prove every DB invariant from Plan 01 on the SQLite suite. Concretely:
- CreditTransaction rows become append-only in the app layer (D-05);
- the only mutation is a status CAS limited to RESERVED -> COMMITTED or RESERVED -> REFUNDED (D-06), proven race-safe on Postgres;
- Django admin becomes a read-only investigation surface for both models.

Purpose: CRED-03 says "no update/delete path exists and status is the only permitted mutation, via named service functions". Phase 30's commit/refund and Phase 31's reaper build directly on `ledger.transition_status`. A double refund or a silent history rewrite would corrupt every balance downstream.

- read-only `admin.py`;
- `tests/helpers.py::assert_ledger_reconciles`;

</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application code → ledger table | Any ORM path (QuerySet bulk ops, instance save/delete) could rewrite settled history |
| Django admin (staff/superuser) → ledger + balance | Investigation surface that must not become an edit surface |
| concurrent settlers (Phase 30 commit vs Phase 31 reaper) → one RESERVED row | Two writers race to settle the same reservation |
