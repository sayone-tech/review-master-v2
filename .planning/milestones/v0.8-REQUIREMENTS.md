## CTAG — Canonical tag model & mapping pipeline (Phase 22)

- [x] **CTAG-01**: Per-org `OrgCanonicalTag` vocabulary (label Title Case ≤3 words, `polarity_type`, `review_count`, timestamps; unique per `(organisation, label)`)
- [x] **CTAG-02**: Each `ReviewTag` carries a nullable `canonical_tag` FK populated once mapped
- [x] **CTAG-03**: The single enrichment GPT call has the org's existing canonical vocabulary injected into its prompt
- [x] **CTAG-04**: GPT maps each generated tag to an existing canonical label, or proposes a new one with a `polarity_type`, in one call
- [x] **CTAG-05**: All tags (raw + canonical) and action items emitted in English regardless of review language
- [x] **CTAG-06**: Post-enrichment lookup/insert + FK populate inside the existing enrichment `transaction.atomic()`
- [x] **CTAG-07**: Every enrichment call still writes exactly one `AiUsageLog` row (canonicalisation adds no separate call)
- [x] **CTAG-08**: Pre-canonicalisation reviews remain valid with a null canonical mapping (backward compatible)

## POL — Polarity types & auto-reclassification (Phase 24)

- [x] **POL-01**: A new canonical tag is assigned `always_positive` / `always_negative` / `mixed` by GPT at creation
- [x] **POL-02**: Weekly Beat job flips `always_*` → `mixed` when opposite polarity exceeds 15% of reviews over 30 days (pure DB aggregation)
- [x] **POL-03**: Reclassification events logged and `polarity_type` visible on the tag list page

## SEED — Four-step initial sync & vocabulary seeding (Phase 23)

- [x] **SEED-01**: Initial sync shows four steps — Fetching Reviews → Building Tag Vocabulary → AI Enrichment → Finalising — with per-step progress text
- [x] **SEED-02**: Seed phase processes the first 50 reviews sequentially (all if fewer), updating vocabulary before each next review
- [x] **SEED-03**: Bulk phase enriches the rest in parallel against the current vocabulary, still able to add new canonical tags
- [x] **SEED-04**: Finalising pass resolves residual duplicate tags by string match and backfills `canonical_tag` on stragglers

## DSYNC — Daily incremental sync (Phase 23)

- [x] **DSYNC-01**: Daily incremental enriches new reviews through the same canonical pipeline on the low-priority queue (new canonical tags auto-added, no approval)

## QUEUE — Infrastructure (queues & rate limiting) (Phases 22–23)

- [x] **QUEUE-01**: Enrichment split across `ai-enrichment-high` (initial) / `ai-enrichment-low` (daily); dedicated `tag-merge` queue isolates merge jobs
- [x] **QUEUE-02**: Global, configurable Celery rate limit (default ~500/min) holding across all workers

## TMGT — Org Admin tag management (Phases 25–26)

- [x] **TMGT-01**: Tags page at `/admin/org/tags/` for Org Admin/Manager (sidebar); Staff cannot reach it
- [x] **TMGT-02**: List shows Label, Polarity Type badge, Review Count, First Seen, Actions — sortable, paginated, query-count-bounded
- [x] **TMGT-03**: Inline rename (1–100 chars, unique within org); updates `OrgCanonicalTag.label` + all mapped `ReviewTag` rows synchronously
- [x] **TMGT-04**: Merge via modal with searchable target picker + "re-maps N reviews, cannot be undone" warning
- [x] **TMGT-05**: Merge runs as a batched `merge_canonical_tags` Celery task (tag-merge queue, per-org lock) re-pointing reviews, deleting source, combining `review_count`, posting completion notification
- [x] **TMGT-06**: Merge progress via HTTP polling — in-progress bar with dismiss, reload-surviving state, completion toast, rollback on failure
- [x] **TMGT-07**: Tags page label **search filter** (server-side, debounced), matching `/admin/org/team/`
- [x] **TMGT-08**: Tags page **header count** ("Tags (N)") + **"Showing X–Y of N · Rows: N"** footer, matching `/admin/org/team/`

## TDASH — Dashboard polarity presentation (Phase 25)

- [x] **TDASH-01**: Dashboard tag charts show a count for `always_*` tags and a positive/negative split for `mixed` tags
- [x] **TDASH-02**: Canonical aggregation queries include only reviews where `canonical_tag` is set
