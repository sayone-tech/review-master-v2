# Milestone Archive: v0.6 — Tag Rework & Action Item Quality

**Shipped:** 2026-05-22
**Phases:** 17–19 (3 phases, 11 plans)
**Requirements:** see [`v0.6-REQUIREMENTS.md`](v0.6-REQUIREMENTS.md) (TAG-01..03, D-01..D-20, plus reply-generation D-01..D-25)
**Git tag:** `v0.6`

## Goal

Improve the day-to-day Org Admin experience over the v0.3 Reviews +
Action Items foundation: a proper relational tagging model with
multi-select filter UI, user-driven merging of duplicate AI-extracted
action items across stores, and AI-drafted reply generation with tone
selection inside the existing ReplyComposer.

## Phases

### Phase 17: Tag Rework — ReviewTag Model and Filter — completed 2026-05-21

**Goal:** Replace `Review.tags` JSONField with a proper `ReviewTag`
relational model; update the AI enrichment pipeline to write rows into
the new table; add a multi-select tag filter with search to the reviews
list UI; and make tag chips on review rows clickable to filter.

**Requirements satisfied:** TAG-01, TAG-02, TAG-03

**Plans (4):**

- [x] 17-01 — ReviewTag model + migration 0008_reviewtag + factory update
- [x] 17-02 — Enrichment service write path + ReviewTagSerializer + prefetch_related
- [x] 17-03 — Tags `@action` endpoint + ReviewFilterSet tags CharFilter + tests
- [x] 17-04 — Frontend: TagsFilter dropdown, clickable chips, ReviewManagementWidget wiring

### Phase 18: Action Item Duplicate Merge — completed 2026-05-22

**Goal:** Allow Org Admins to mark action items as duplicates of one
another, merging them under a canonical item. Duplicate items are
hidden from the default list, the canonical shows a "+N" badge, and a
detail section lists all duplicates with links.

**Requirements satisfied:** D-01 .. D-20

**Plans (4):**

- [x] 18-01 — ActionItem canonical FK + migration 0003_actionitem_canonical + model tests
- [x] 18-02 — Backend: merge service + lifecycle guards + selector filter/annotation + serializers + merge API endpoint + full test suite
- [x] 18-03 — Frontend list: DataTable checkbox extension + ActionItemTable + MergeModal + toolbar + types/api
- [x] 18-04 — Frontend detail: DuplicatePickerModal + "Also reported in" + "Mark as duplicate of…"

### Phase 19: AI Reply Generation — completed 2026-05-22

**Goal:** Org Admins and Staff can generate an AI-drafted reply inside
the ReplyComposer by clicking "Generate with AI", selecting Professional
or Friendly tone, and reviewing the draft before submitting it manually
— powered by GPT-4o-mini with full AiUsageLog cost tracking.

**Requirements satisfied:** D-01 .. D-25 (from 19-CONTEXT.md)

**Plans (3):**

- [x] 19-01 — Backend service layer: `REPLY_GENERATION_PROMPT_VERSION`, `build_reply_generation_messages()`, `call_openai_reply_generation()`, `generate_reply_draft()` + AiUsageLog write + tests
- [x] 19-02 — API endpoint: GenerateReplySerializer, `generate_reply` `@action` on ReviewViewSet, throttle rate, endpoint tests
- [x] 19-03 — Frontend: `generateReply()` in api.ts, generator button + tone pills + confirmation row + state machine + focus management in `ReplyComposer.tsx`

**Cross-cutting constraints satisfied:**
- Every OpenAI call writes one AiUsageLog row (CLAUDE.md §14)
- `select_related("shop__organisation")` on `ReviewViewSet.get_queryset()` (CLAUDE.md §6)

## Key Accomplishments

- **Relational ReviewTag model** — JSONField → proper table with
  `(review_id, label, polarity)`, case-insensitive dedup per org
- **Tags multi-select filter UI** with search and clickable chips,
  AND-semantics tag filtering on reviews list
- **Action item merge workflow** — checkbox-select multiple items →
  two-step modal → canonical with "+N" badge; merged items become
  read-only; "Mark as duplicate of…" picker on individual items
- **AI reply generation** with Professional/Friendly tone — GPT-4o-mini
  generates draft, user reviews + edits + manually submits
- **Cost tracking unchanged** — every reply generation writes an
  AiUsageLog row with `request_type="reply_generation"`
