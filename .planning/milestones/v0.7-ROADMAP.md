# Milestone Archive: v0.7 — AI Safety & Governance

**Shipped:** 2026-05-24
**Phases:** 20–21 (2 phases, 12 plans)
**Git tag:** `v0.7`

## Goal

Add safety controls around every OpenAI call (Moderation API
input/output checks, content length truncation, sentence-boundary reply
caps) and a read-only Activity Log surfacing reply + action item audit
events to Org Admins and Staff. This is the final milestone of the
**first web beta** — the platform is now production-safe to use across
the AI surface area and auditable to its tenant administrators.

## Phases

### Phase 20: AI Guardrails — completed 2026-05-23

**Goal:** Add input/output safety controls around all OpenAI calls.
MVP scope: NO token budget, NO per-org AI toggle (deferred to a future
pricing phase).

**Plans (8):**

- [x] 20-01 — Settings: `OPENAI_REVIEW_TEXT_MAX_CHARS` env-configurable + `.env.example`
- [x] 20-02 — `ContentModeratedException(OpenAIError)` in `exceptions.py`
- [x] 20-03 — Schema: `AiUsageLog.Status.MODERATED` enum + `Review.enrichment_error_code` field + migrations
- [x] 20-04 — `apps/integrations/openai/guardrails.py`: `BLOCKING_MODERATION_CATEGORIES` (underscore form), `_moderate_with_retry` (fail-open), `moderate_input`, `moderate_output`, `truncate_reply_at_sentence`, `_persist_moderated_log` + unit tests
- [x] 20-05 — Service wiring: `enrich_review` calls `moderate_input` outside atomic; `_persist_moderated` helper sets `enrichment_error_code`; tests
- [x] 20-06 — Service wiring: `generate_reply_draft` calls `moderate_input` → OpenAI → `moderate_output` → `truncate_reply_at_sentence`; output-moderation `AiUsageLog` carries real tokens; tests
- [x] 20-07 — View: `ReviewViewSet.generate_reply` catches `ContentModeratedException` → HTTP 422 with canonical copy; tests
- [x] 20-08 — Retry task: `retry_failed_enrichments_task.exclude(enrichment_error_code="content_moderated")`; tests

**Behaviours shipped:**

- Review text >4000 chars (env-configurable) truncated with `"…[truncated]"` before any OpenAI call
- High-severity moderation categories block enrichment with `Review.enrichment_status=FAILED`, `enrichment_error_code="content_moderated"`
- AI reply: input moderation blocks before OpenAI; output moderation blocks before user; replies >300 words truncated at sentence boundary with `" (Please review and complete before sending.)"`
- `ContentModeratedException` → HTTP 422 with canonical body
- Moderation API outage: fail-open with one retry after 1s; ERROR log on second failure
- `AiUsageLog` rows for moderated events: input → status=MODERATED + zero tokens; output → status=MODERATED + real tokens + error_code="output_moderated"
- `retry_failed_enrichments_task` excludes rows with `enrichment_error_code="content_moderated"`
- All `AiUsageLog` writes for moderation events happen OUTSIDE any `transaction.atomic()` block (audit-row survival on rollback)

### Phase 21: Audit Log Viewer — completed 2026-05-24

**Goal:** Read-only "Activity Log" page in the Org Admin UI showing
reply and action item audit events; Staff-scoped to accessible shops
and SHOP-scope action items only; cursor-paginated; filterable by
type, date range, actor.

**Plans (4):**

- [x] 21-01 — Selectors (`list_audit_logs_for_org/staff`), `AuditLogReadSerializer`, `AuditLogCursorPagination`, `AuditLogFilterSet`, selector tests
- [x] 21-02 — `AuditLogViewSet` in `apps/common/views.py` + `audit_log_view` + URL registration + settings throttle + API tests
- [x] 21-03 — Django template `templates/org-admin/audit-log.html` + sidebar Activity Log nav item
- [x] 21-04 — React widget: types, utils, api, `useAuditLog` hook, `TypePill`, `AuditLogFilters`, `AuditLogTable`, `AuditLogWidget` + vite entrypoint

**Behaviours shipped:**

- `GET /api/v1/audit-logs/` returns cursor-paginated results scoped to caller's org; Staff receives only entries from their accessible shops + SHOP-scope action items (CLAUDE.md §9 layer-1 defence)
- Filters: `entity_type` (review/action_item), `actor` (user ID or "system"), `date_from`/`date_to` (ISO date), `shop`
- Superadmin receives 403; unauthenticated receives 401; throttle 120/minute
- "Activity Log" nav item appears in `sidebar_org.html` for both `ORG_ADMIN` and `STAFF_ADMIN`
- `/admin/org/activity-log/` renders Django template with React widget at `#audit-log-root`
- 5-column table with expandable JSON detail panel, Type pills (Reply / Action Item), cursor pagination, filter bar with 30d default date preset

## Key Accomplishments

- **Production-safe AI** — every OpenAI surface (enrichment + reply
  generation) now passes input and output through the Moderation API,
  with category-aware blocking on high-severity content. Failed calls
  produce an auditable `AiUsageLog` row.
- **Content length limits** — reviews truncated at 4000 chars (env-cap),
  reply drafts capped at 300 words with sentence-boundary cleanup.
- **Audit trail visible to tenants** — reply and action item events
  cross-referenced in a paginated, filterable Activity Log scoped to
  the caller's org and (for Staff) accessible shops only.
- **Resilience** — moderation API outage fails open with retry; audit
  log writes happen outside transactions so failed enrichments still
  leave a trail.
