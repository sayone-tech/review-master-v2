## Goal

Normalise inconsistent AI-generated review tags into a self-organising,
per-organisation canonical vocabulary so tag-based analytics (trending
topics, dashboard charts, action-item grouping) are reliable — built and
evolved **entirely inside the existing single GPT enrichment call**, with
no extra API call and no vector DB. Initial sync became a visible
four-step flow with a sequential vocabulary-seed phase; Org Admins gained
direct tag curation (rename / merge); and sync-progress was hardened to be
live and trustworthy end-to-end.

**Source spec:** `docs/completed/ReviewBee_Canonical_Tag_Requirements_v1.0.md`
(v1.0, Final), reconciled against the live schema (`.planning/research/SUMMARY.md`)
— key correction: tags are the relational `ReviewTag` model (v0.6 Phase 17),
not the JSONB column the spec assumed; canonical mapping attaches as a
nullable FK on `ReviewTag`.

## Key Accomplishments

- **Self-organising canonical vocabulary** — per-org `OrgCanonicalTag` built and evolved
  inside the *existing* single GPT call (no extra API call, no vector DB); `ReviewTag.canonical_tag`
  FK with label held FK-only so renames are O(1); exactly one `AiUsageLog` row per enriched review.
- **Visible four-step initial sync** — Fetch → Build Tag Vocabulary (sequential 50-review seed)
  → AI Enrichment (parallel bulk) → Finalising, surfaced by extending the single
  `SyncProgressConsumer` (no new consumer); split `ai-enrichment-high`/`-low` + `tag-merge` queues.
- **Self-maintaining polarity** — GPT-assigned `always_*`/`mixed` at creation; weekly DB-only Beat
  job flips `always_*` → `mixed` past the 15% / 30-day threshold; each flip writes one `AuditLog` row.
- **Org Admin tag curation** — Tags page with sortable/query-bounded list, inline rename, and merge
  (per-org-locked Celery task, HTTP-polled `TagMergeJob` progress with rollback); dashboard polarity split.
- **Trustworthy sync progress** — snapshot-poll fallback + org-scoped GET endpoint so the modal
  self-heals on missed WebSocket events; finalise completion-gating so Finalising fires when bulk
  enrichment actually completes (no fixed long countdown) and the step is visible.

## Milestone Summary

**Key Decisions:**

- Tag-merge progress uses **HTTP polling**, not a new WebSocket consumer — keeps the Channels surface narrow (§13.2).
- Tags are the relational `ReviewTag` model (not JSONB); canonical mapping attaches as a nullable FK; `OrgCanonicalTag` carries a direct `organisation` FK.
- Canonical lookup/insert folds into the existing single GPT call + post-enrichment write inside enrichment.py's `transaction.atomic()` — never a separate GPT call.
- `review_count` is derive-on-read (never incremented inline; excluded from `bulk_update` field lists outside the refresh path).
- SYNC-REL-02 finalise gate uses a bounded self-reschedule, not a Celery chord (deferred).
- Incremental cadence settled at 6-hourly (`0 */6 * * *` UTC).

**Issues Resolved (during UAT):**

- Worker `-Q` updated to consume the v0.8 split queues (bulk enrichment had stalled at 0).
- Finalising snapshot preserves `fetched`/`enriched` (was showing "N of 0").
- Bulk enrichment bumps `last_update_at` (modal no longer looked frozen).
- Seed-dependent test flake in `ReviewTagFactory` (Faker word collision on the unique constraint) fixed with a deterministic Sequence label.

**Issues Deferred:**

- Phase 28 / RESET-01..03 — Superadmin in-app data reset, parked until a production deployment exists.
- Optional follow-up: extract the shared shop-access scope check between `SyncProgressSnapshotView` and `SyncProgressConsumer` into one selector (drift risk).
- Phase 25/26 browser-UAT items verified manually end-to-end by the user post-merge.

**Technical Debt Incurred:**

- Duplicated shop-access scope check across the snapshot view and the consumer (LOW; flagged above).
