## Surface Specifications

### Surface 1: Team List Page `/admin/org/team`

**Layout:** Standard org-admin shell (sidebar + main content area)

**Page header row:**
- Left: page title "Team" (`text-[20px] font-semibold text-ink`) + member count in parentheses (`text-[16px] text-muted`)
- Right: "+ Add Team Member" button — `bg-yellow text-black border-yellow-hover hover:bg-yellow-hover px-3.5 py-2 text-[13.5px] font-semibold rounded-md` — matches "Add Shop" button pattern exactly

**Stats cards row (3 cards, equal width, horizontal flex, gap-4):**
- Each card: `bg-white border border-line rounded-card p-4`
- Number: `text-[24px] font-semibold text-ink`
- Label: `text-[12px] font-medium text-muted mt-0.5`
- Cards: "Total Members" (Users icon), "Managers" (Crown icon), "Active Members" (CheckCircle icon)
- Icon: Lucide, size 18, `text-subtle`, displayed top-right of card

**Solo-member info banner (TEAM-05):**
- Appears only when Org Admin is the only team member
- `bg-yellow-tint border border-yellow/40 rounded-md px-4 py-3`
- Text: `text-[13.5px] text-ink` — "You're the only team member." + inline "+ Add Team Member" link (`text-yellow-hover underline font-medium`)

**Filters row:** search input + Region dropdown + Store dropdown (Store narrows when Region selected)
- Input class: `px-3 py-2 text-[13.5px] bg-white border border-line rounded-md focus:outline-none focus:ring focus:ring-black/[0.06] focus:border-ink`
- Search placeholder: "Search name or email…"
- Region dropdown: "All Regions" default
- Store dropdown: "All Stores" default, disabled with tooltip "Select a region first" when no region selected

**Table columns:**
1. MEMBER — Name (`text-[13.5px] font-semibold text-ink`) + Email (`text-[12px] text-muted`)
2. ROLE — RoleBadge (Manager/Staff)
3. ACCESS — AccessChips (crown pill for Manager; region/store chips with "+N more" for Staff)
4. STATUS — dot + label badge (Active/Pending/Disabled)
5. INVITED — date formatted as "DD Mon YYYY"
6. ENABLED — toggle (ON/OFF) — own row toggle is disabled with tooltip "You cannot disable yourself."
7. (actions column) — Edit icon button + Remove icon button — both disabled on own row with tooltip

**Action buttons per row:**
- Edit: Pencil icon, `w-8 h-8 text-subtle hover:text-ink` — disabled for own row
- Remove: Trash2 icon, `w-8 h-8 text-subtle hover:text-red` — disabled for own row AND for last Manager row
- Disabled state: `opacity-40 cursor-not-allowed pointer-events-none`
- Disabled tooltip: use `title` attribute (native browser tooltip — matches Phase 7/8 pattern)

**Pagination:** identical to ShopTable — "Showing X–Y of Z" left, rows-per-page selector (10/25/50/100) + Prev/Next right

**Empty state:** Users icon, "No team members yet.", "Add your first team member" CTA

**Skeleton loading:** 6 skeleton rows via DataTable `loading` prop — matches existing pattern

## Interaction Contracts

### Enabled Toggle (TEAM-10, TEAM-11)
- **ON → OFF (disable):** Click opens `DisableMemberModal` (amber confirm). On confirm: API call, success toast "{Name} disabled.", row updates — Enabled=OFF, Status=Disabled
- **OFF → ON (enable):** Click directly (no confirm). Optimistic update: toggle flips immediately. On API failure: revert + error toast
- **Own row:** Toggle is `disabled` with `title="You cannot disable yourself."` and `opacity-40 cursor-not-allowed`
- **Toggle visual:** Custom inline toggle — `w-10 h-6` pill, `bg-green` when ON, `bg-line` when OFF, white circle knob `w-4 h-4`; `transition-[background,transform]` 150ms

### Access Chips Truncation (TEAM-01)
- Show first 2 chips inline
- If more than 2 scopes: render "+N more" chip (`bg-line-soft text-muted text-[12px] rounded-full px-2 py-[2px]`)
- N = total count minus 2
- No expand-on-click behavior in v1 (deferred)

### Self-Protection (TEAM-14)
- Detect own row: `member.id === currentUserId` — `currentUserId` seeded from template via `data-current-user-id` attribute on mount element
- Own row: Edit button disabled with `title="You cannot edit yourself."`, Remove button disabled with `title="You cannot remove yourself."`
- API-layer 403 is the final safety net — UI disables are first line of defense

### Last-Manager Guard (TEAM-15)
- Detect: `member.role === "MANAGER"` AND `managerCount === 1`
- Remove button disabled with `title="Cannot remove the last Manager."`
- `managerCount` derived from stats card data (live count from API)

### Store Dropdown Narrowing (TEAM-02)
- When Region filter changes: Store filter resets to "All Stores" and re-fetches store options filtered to that region
- In Add/Edit modal scope section: Store multi-select resets checked state when Regions selection changes

### Role Change in Edit Modal (TEAM-08)
- Manager → Staff: scope section slides in (not animated in v1 — use conditional render `{role === "STAFF" && <ScopeSection />}`)
- Staff → Manager: scope section unmounts; any checked regions/stores are cleared

### CustomEvent Bus (matches Phase 7/8 pattern)
Events dispatched from `TeamTable`, subscribed in `TeamModals`:
- `team:open-edit` — detail: `TeamMemberRow`
- `team:open-remove` — detail: `TeamMemberRow`
- `team:open-disable` — detail: `TeamMemberRow`
- `team:open-resend` — detail: `TeamMemberRow`

Events dispatched from `TeamModals` to `TeamTable` (list refresh):
- `team:member-added` — triggers list refetch
- `team:member-updated` — triggers list refetch
- `team:member-removed` — triggers list refetch
- `team:member-toggled` — triggers list refetch

## Accessibility Contract

- All icon-only buttons have `aria-label` (e.g. `aria-label="Remove {name}"`)
- Disabled buttons use both `disabled` attribute and `title` for tooltip (native browser behavior, no custom tooltip library)
- ConfirmModal inherits `role="dialog" aria-modal="true"` from Modal.tsx
- Enabled toggle: `role="switch"` + `aria-checked={enabled}` + `aria-label="{name} enabled"`
- Region/Store multi-select lists: `role="group"` + `aria-label="Region access"`
- Focus trap: inherited from Modal.tsx (focus-trap-react already in use)
- Status badges: include screen-reader text for dot indicator via `aria-hidden="true"` on the dot span
- Error messages: `role="alert"` — matches existing pattern in CreateShopModal / invite_accept.html
