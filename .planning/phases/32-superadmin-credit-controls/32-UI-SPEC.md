# Phase 32 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope (Superadmin-only surfaces, all inside the existing org-management widget):**
1. "Monthly credits per shop" field + live inline hint on Create and Edit Organisation (CRED-01, CRED-06, D-01..D-04)
2. "Credits/shop" column in the organisations table and mobile card (D-14)
3. Allocation + pending-change note in View Organisation (D-15)
4. "Manage Credits" row action and modal: shop list view and bonus form view (CSUP-01, D-05..D-13, D-16, D-17)

**Sources:** locked decisions D-01..D-17 from `32-CONTEXT.md` (not re-asked); copy/validation from `Requirements_Credits_System.md` §8.1/§8.2; visual tokens and shells read directly from `frontend/src/widgets/org-management/*`, `frontend/src/widgets/modal/Modal.tsx`, `frontend/tailwind.config.js`, `templates/components/{toasts,pagination,filter_bar}.html`. Everything not marked "default" below is taken from one of those.

**Nothing new is introduced** — no new color, font size, weight, radius, icon library, or dependency. The only new compositions are listed in "New Compositions (no direct precedent)" and are built from existing tokens.

## Spacing Scale

Declared values (multiples of 4) used by every NEW element in this phase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Label-to-input gap (`mb-1`), icon gaps, hint top margin (`mt-1`), pill vertical padding (`py-1`) |
| sm | 8px | Vertical padding of new rows' sub-elements (`py-2`: amber note, preview box, pagination bar), pill horizontal padding (`px-2`), gap between footer buttons (`gap-2`), gap between preview segments, search icon inset (`left-2`), note top margin (`mt-2`) |
| md | 16px | Form field stack (`space-y-4`), shop-row padding (`px-4 py-4`), amber note / preview box / pagination bar / in-list button horizontal padding (`px-4`), stat-block padding (`p-4`), gap between modal sections (`mt-4`) |
| lg | 24px | Modal horizontal padding (shell-owned `px-6`) |
| xl | 32px | Empty/error state vertical padding (`py-8`), search input left padding (`pl-8`, clears the 16px icon inset 8px), in-list control height (`h-8`) and pagination arrow size (`h-8 w-8`) |
| 2xl | 48px | not used |
| 3xl | 64px | Skeleton row height (`h-16`) |

Control heights (all multiples of 4, set with explicit `h-*`, not derived from padding): footer buttons `h-10` (40px, `px-4`); in-list buttons (`Add bonus`, `Retry`, `Clear search`) and pagination arrows `h-8` (32px; arrows `w-8`, in-list buttons `px-4`). The preview box `min-h-[56px]` reserves its two-line height so layout does not shift.


Exceptions (exhaustive, each named with a justification):
1. **`inputCls` (`px-3 py-2`, 12px horizontal) on the four new form controls only**: "Monthly credits per shop" (Create + Edit), bonus "Additional credits to allocate", and bonus "Reason" textarea. 12px is a multiple of 4 but not on the scale; kept because the class string is imported/copied unchanged from the shipped "Number of Stores" / Address inputs and these fields must be pixel-identical to their neighbours in the same forms and to `StoreAllocationModal`'s inputs. The search field is NOT in this exception (it uses `pl-8 pr-4 py-2`).
2. Shared shell internals, untouched and not specified by this phase: `py-[11px]` table header and `px-6 pt-[22px]` modal header. (This phase's own footer buttons are specified above as `h-10 px-4`.)
3. **Touch targets: 32px (`h-8`) in-list buttons and arrows are below the 44px mobile target.** Rationale: Manage Credits is a Superadmin-only, desktop-first back-office tool; 32px exceeds the WCAG 2.2 SC 2.5.8 minimum of 24×24 CSS px. 44px is not enforced.

## Interaction Contract

### A. Create / Edit Organisation field
- Input: `type="number"`, `min=0`, `max=10000`, `step=1`, `inputMode="numeric"`, same `inputCls` as "Number of Stores". Not `required` in Edit (value always present); Create prefilled `"0"`.
- Client validation on submit mirrors existing forms (`errors.monthly_credit_allocation`); server field errors keyed `monthly_credit_allocation` surface through the existing `ApiError.fieldErrors` path.
- Static helper + live hint sit in one wrapper `div` under the input; input gets `aria-describedby` pointing at it. Only the amber/muted live line carries `aria-live="polite"`.
- Edit modal: N is the org's saved `monthly_credit_allocation` captured when the modal opens (resets with `org` like the other fields). Payload includes the field only alongside the other fields (existing `updateOrg` call); backend writes `organisation.credits.set` only on real change.
- `date` computed in UTC (server period is UTC) so the 1st-of-next-month never disagrees with the backend at month boundaries.
- Test ids: `field-monthly_credit_allocation` (Create), `edit-field-monthly_credit_allocation` (Edit), `credit-allocation-hint` (live line).

### B. Table column and View modal
- Column `key: "credits"`, inserted after `stores`, `skeletonWidth: "56px"`. Mobile `OrgCard` gets a matching `dt/dd` row between Stores and Created.
- View Org: new `dt`/`dd` after "Stores". The pending pill renders only when the API reports a current-month value different from the saved field; it is read-only (no link/action).
- `OrgRow` gains `monthly_credit_allocation: number` and a current-month value (e.g. `current_month_credit_allocation`) so the UI needs no extra request; exact field names are the planner's call (D-15).

### C. Manage Credits modal (one `Modal`, `size="lg"`, internal `view: "list" | "bonus"` state — NOT two stacked modals)
Wiring: add `onOpenManageCredits` to `OrgTableHandlers`, `window._orgModalHandlers`, and a `creditsRow` state in `org-management.tsx`, exactly like `onOpenAdjustStores`. No `onDone` refresh of the org table is needed (the table shows allocation, not balances).

**List view**
- Layout (top to bottom): search field → list container → pagination bar. Search uses the `filter_bar.html` look: `Search` icon 16px at left inside `bg-bg border border-line rounded-md` input, `pl-8 pr-4 py-2 text-[13px]` (icon inset `left-2`), focus `border-ink ring ring-black/[0.05]`, `type="search"`.
- Search is server-side, debounced 300ms, resets to page 1, ignores stale responses. Case-insensitive contains-match on shop name (default; planner may narrow to prefix per D-07 discretion). Clearing the input reloads immediately.
- Page size 10 (default; no per-page selector in the modal). Pagination bar: `px-4 py-2 border-t border-line bg-[#FBFBFB] text-[13px] text-muted`, `h-8 w-8` (32×32px) `rounded-sm bg-white border border-line` `ChevronLeft`/`ChevronRight` buttons, disabled = `opacity-40 cursor-not-allowed`. Count text `aria-live="polite"`.
- List container: `bg-white border border-line rounded-card overflow-hidden mt-4`; the Modal body already scrolls (`max-h-[80vh]`), do not add a nested scroller.
- Shop row (`<li>`, `px-4 py-4`, divider `border-b border-line-soft`, last row no divider): `flex flex-col gap-2 sm:flex-row sm:items-center sm:justify-between sm:gap-4`.
  - Left (min-w-0): shop name 14/600 `text-ink` `break-words`; below it breakdown 12/400 `text-subtle`.
  - Right (`flex items-center gap-4 shrink-0`): `Remaining` 12 `text-muted` + value 14/600 `text-ink`, then the `Add bonus` secondary button (`h-8 px-4 text-[13px] font-normal`, 32px tall; touch-target exception 3 in Spacing).
  - On <640px the right block drops under the left and the button stays inline-sized (not full width).
- Virtual balances (shop without a current-month row) render identically — remaining equals the full allocation; the list never creates rows (D-06).
- Active shops only (D-05); inactive shops never appear.
- Clicking `Add bonus` switches to the bonus view for that row using the row data already loaded (no extra fetch).
- Initial focus on open: the search input. Esc / X / backdrop / `Close` close the whole modal (shell behaviour; state is discarded).

**Bonus view**
- Layout (top to bottom): balance block → Amount field → preview → Reason field → (409 banner when present, placed directly above the balance block so it is the first thing read).
- Balance block: `bg-line-soft rounded-md p-4`, `dl` as a 4-column grid (`grid-cols-2 sm:grid-cols-4 gap-4`); each cell: label 12 `text-subtle` uppercase tracking `[0.05em]` over value 14/600 `text-ink`. Values are the CURRENT balances (before the typed amount).
- Amount: label style identical to Create's `Field` label; input `type="number" min=1 max=10000 step=1 inputMode="numeric"`, `inputCls`. Validity is live: empty = neutral; non-integer or outside 1–10,000 = red 12px `role="alert"` message and red border; valid = clear. Initial focus lands here when the view opens.
- Preview: `mt-4`; an outlined box (not filled, so it reads as distinct from the filled balance block): `border border-line rounded-md px-4 py-2 text-[13px]`, min-height reserved (`min-h-[56px]`) so the layout does not shift when it appears. Caption `After this allocation` (12 `text-subtle`) above the line. Before-values `text-muted`, after-values `text-ink` 600, arrow `→` literal, segments separated by ` · `. `aria-live="polite"`. Shown only while the amount is valid; otherwise the placeholder sentence.
- Reason: `textarea rows=3 maxLength=255` (matches `CreditTransaction.note` `max_length=255`), same `inputCls`; no counter.
- Footer: `Back to list` + `Allocate` (both `h-10 px-4 text-[14px]`, as are `Close` in the list view). `Allocate` is disabled (`opacity-50 cursor-not-allowed pointer-events-none`, StoreAllocation precedent) while the amount is empty/invalid, while submitting, and while a 409 reload is in flight. `Back to list` is disabled while submitting; it discards typed values.
- Submit: POST with shop, amount, optional reason (empty string -> omitted), and the **displayed period** (echoed for the 409 check). Button shows the existing 16px `animate-spin` spinner left of the label; inputs `disabled` during the request. Double-submit is impossible (button disabled on first click; handler early-returns).
- **Success (D-11):** emit success toast → switch to list view → reload the current page/search of the list (keep search text and page) → apply a 3-second static `bg-yellow-tint` highlight to the updated shop's row (no animation, clears on timeout or next interaction) → move focus to that row's `Add bonus` button.
- **409 period mismatch (D-12):** show the amber banner (same classes as the deferred-hint note, `role="alert"`), reload that shop's balances/period in place (balance block and subtitle month switch to the new month; block shows skeleton pulses while reloading), keep amount and reason as typed, recompute the preview against the new numbers, and require the user to press `Allocate` again (no auto-resubmit). The banner clears on the next edit of amount/reason or on success/back.
- **400 field error:** server error for `amount` / `reason` renders under that field (red 12px); no toast.
- **404 / inactive shop:** error toast (copy above), return to list and reload.
- **Other errors / network:** generic error toast; form and values unchanged; button re-enabled.

### D. Keyboard and a11y summary
- All new controls reachable by Tab in DOM order; focus trap is the shell's `FocusTrap`. Icon-only controls (pagination arrows) carry `aria-label`s; decorative icons `aria-hidden="true"`.
- Every input has a visible `<label>` bound by `htmlFor`/`id`; error text uses `role="alert"`, hints/notes `role="status"`.
- Contrast: all new text pairs are existing token pairs at or above 4.5:1 (`ink`/`muted`/`subtle` on white or `#F4F4F5`; `#92400E` on `#FEF3C7`; `#991B1B` on `#FEE2E2`).
- No motion beyond the existing spinner and skeleton pulse; the row highlight is static, so `prefers-reduced-motion` needs no special handling.
