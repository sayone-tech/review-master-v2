**Review text "Show more" (in DataTable row — column or expanded card view):**

- Truncated: shows first 1000 chars + "… Show more" appended inline (`text-[12px] font-semibold text-ink underline cursor-pointer`)
- Expanded: shows full text + "Show less" at end (same style)

**Pagination:** Cursor-based; UI shows "Showing X–Y of Z" (total from API count annotation). Controls: rows-per-page selector (10/25/50/100) on the right; Prev / Next buttons — no jump-to-page (cursor limitation). Matches ShopTable pagination visual pattern exactly.

## Interaction Contracts

### Reply Composer Expand/Collapse

Decision (Claude's discretion): Accordion pattern — inline row expansion, NOT a drawer.

Rationale: The CONTEXT.md specified "accordion / slide-out drawer" as alternatives. Accordion chosen because:
- Keeps full context visible: reviewer, stars, shop, date remain visible above composer without layout shift
- Consistent with the DataTable "expanded row" pattern common in dense admin tables
- Lower implementation complexity than a drawer (no z-index/portal management)

Implementation:
- `ReviewTable` tracks `openComposerId: string | null` in state
- Clicking "Reply" on a row sets `openComposerId = review.id`; clicking again or "Discard Reply" sets `null`
- An extra `<tr className="border-b border-line">` is inserted after the review row when `openComposerId === review.id`
- The extra row uses `<td colSpan={totalColumns}>`

### Reply Submit Flow

1. User types reply in `<textarea>` (max 4000 chars)
2. Clicks "Submit Reply" → button enters "Submitting…" + disabled state
3. `POST /api/v1/reviews/{id}/reply/` with `{ comment: "..." }`
4. On 200: composer replaced with replied view (green CheckCircle + "Replied on {date}" + reply text read-only); `ReplyStatusBadge` in row updates to "Replied"; green toast "Reply posted."
5. On error: inline error banner appears below textarea ("Failed to post reply. Please try again."); button re-enabled; composer stays open

### Topbar Badge Lifecycle

1. On mount: `GET /api/v1/shops/syncing/` — initial count
2. Per shop in list: WebSocket to `/ws/sync-progress/{shop_id}/`
3. `sync.complete` received → remove shop from active list → decrement count → badge hides if count reaches 0
4. `sync.error` with permanent failure → move shop to failure list → badge turns red
5. "View progress" click → navigate to `/admin/org/shops/?open_progress={shop_id}` → Shops page opens `ProgressModal` for that shop

### OAuth → Progress Modal Trigger

1. OAuth callback handler redirects to `/admin/org/shops/?open_progress={shop_id}`
2. Shops page React widget reads `URLSearchParams` for `open_progress` on mount
3. If present: immediately renders `ProgressModal` for that `shop_id`
4. `ProgressModal` on mount: reads `GET /ws/sync-progress/{shop_id}` WebSocket and receives Redis snapshot immediately (PROG-09)
5. Query param cleared from URL after modal opens (use `history.replaceState` — no page reload)

### Filter Chip Dismissal

- Clicking `×` on any chip removes that filter value and triggers API refetch
- "Clear all" removes all active filters simultaneously

### Review Text Truncation

- If `comment.length <= 1000`: render full text, no toggle
- If `comment.length > 1000`: render `comment.slice(0, 1000)` + `"…"` + "Show more" span
- "Show more" click: local component state flips to expanded; renders full text + "Show less"

### CustomEvent Bus (matches Phase 8/9 pattern)

Events dispatched from `ReviewTable`:
- (none — reply is handled inline; no cross-component events needed in Phase 11)

Events dispatched from `TopbarSyncIndicator`:
- (none — navigates via `window.location.href`)

## Accessibility Contract

- Star rating cells: `aria-label="N out of 5 stars"` on the star group container
- "Show more" button: `aria-expanded={false|true}` on the toggle; `aria-controls="review-text-{id}"`
- Reply composer textarea: `aria-label="Write your reply"` + `aria-describedby="char-counter-{id}"`
- Char counter span: `id="char-counter-{id}"` + `aria-live="polite"` (updates announced to screen readers)
- Progress bars: `role="progressbar"` + `aria-valuenow` + `aria-valuemin="0"` + `aria-valuemax="100"` + `aria-label="Fetched from Google: N%"`
- "Run in background" button: `aria-label="Run sync in background and close this dialog"`
- "View Shop Details" button (disabled): `aria-disabled="true"` when not yet enabled
- Topbar badge: `aria-live="polite"` container — count changes are announced
- Topbar dropdown: `role="menu"` + `aria-label="Syncing shops"` on dropdown panel
- Reply inline error: `role="alert"` — announced immediately on failure
- Filter chips: each chip dismiss button has `aria-label="Remove {filter name} filter"`
- Anonymous reviewer: screen-reader text "Anonymous reviewer" (not just "Anonymous")
- Modal (ProgressModal): inherits `role="dialog" aria-modal="true"` from Modal.tsx; `aria-label="Syncing {shop_name} Reviews"`
- All icon-only buttons: `aria-label` set explicitly
- Row actions menu (`•••` button): `aria-label="More actions for this review"`
- Focus trap: inherited from Modal.tsx (focus-trap-react)
