<objective>
Wire the enrichment pipeline into the live sync flow and the progress UI: (1) enqueue
`enrich_review_task` for every upserted PENDING review in `fetch_and_persist_reviews`,
(2) remove the now-stale `sync.complete` emission from the fetch loop and move that
responsibility to the enrichment service, (3) emit `sync.enrichment.progress` events
from the enrichment success path with a snapshot-aware running counter, gating
`sync.complete` until `enriched >= fetched`, and (4) seed the
`retry_failed_enrichments_task` Beat schedule (6-hourly, ai-enrichment queue) via a
data migration.

Purpose: Phase 11 emitted `sync.complete` after the fetch loop because enrichment
did not exist. CONTEXT.md locks the new behaviour: "sync.complete fires only when
total_enriched >= total_fetched." Without this plan, the ProgressModal's "Sync
complete" banner appears after fetch (incorrect — the green AI bar would still be
filling). This plan also closes the missing inline enqueue (otherwise newly fetched
reviews would never be enriched until the Beat retry task picks them up) and the
missing Beat seed for ENRCH-06's 6-hour retry cadence.

Output: Two service-file edits, one new test file (`test_enrichment_progress.py`),
additions to the existing sync test file, and one Beat seed data migration.
</objective>

**Inline enqueue contract (sync.py):**

After `_persist_page` upserts a page of reviews, query for the IDs that are
currently in `PENDING` state for that shop and that page's `google_review_id`

```python
# apps/reviews/services/enrichment.py — new helper called from _persist_success

def _emit_enrichment_progress(*, review: Review) -> None:
    """Emit sync.enrichment.progress after a successful enrichment.

    Reads the current Redis progress snapshot (sync:progress:{shop_id}) to
    pick up running totals. If no snapshot exists (incremental sync with no
    live modal), returns silently — no event needed.

    On every successful enrichment, increments the snapshot's `enriched`
    counter and writes it back. Emits sync.enrichment.progress with the
    new running counts. When enriched >= fetched (and fetched > 0), emits
    sync.complete as the SOLE source of that event in Phase 12.
    """
    from apps.reviews.services.progress import (
        read_progress_snapshot,
        write_progress_snapshot,
    )
    from apps.reviews.services.sync import emit_progress_event

    shop_id = review.shop_id
    snapshot = read_progress_snapshot(shop_id=shop_id)
    if snapshot is None:
        return  # No live progress modal -> no WebSocket event needed

    enriched = int(snapshot.get("enriched", 0)) + 1
    fetched = int(snapshot.get("fetched", 0))

    new_snapshot = {**snapshot, "enriched": enriched}
    if fetched > 0 and enriched >= fetched:
        new_snapshot["status"] = "success"
    else:
        new_snapshot["status"] = "enriching"
    write_progress_snapshot(shop_id=shop_id, data=new_snapshot)

    emit_progress_event(
        shop_id=shop_id,
        payload={
            "type": "sync.enrichment.progress",
            "shop_id": shop_id,
            "enriched": enriched,
            "fetched": fetched,
        },
    )

    if fetched > 0 and enriched >= fetched:
        emit_progress_event(
            shop_id=shop_id,
            payload={
                "type": "sync.complete",
                "shop_id": shop_id,
                "total_fetched": fetched,
                "total_enriched": enriched,
                "duration_seconds": snapshot.get("duration_seconds"),
            },
        )
```

The helper is called from `_persist_success` AFTER the `transaction.atomic()`
block commits — emitting events during a transaction is an anti-pattern
(RESEARCH.md anti-patterns: "Calling emit_progress_event inside transaction.atomic()").

```python
def _emit_enrichment_progress(*, review: Review) -> None:
    """Phase 12 progress emission after a successful enrichment.

    Reads sync:progress:{shop_id} from Redis. If absent (incremental sync with
    no live ProgressModal client), returns silently — no WebSocket event.

    On success, increments the snapshot's `enriched` counter, writes it back,
    and emits sync.enrichment.progress. When enriched >= fetched (and
    fetched > 0), also emits sync.complete — the SOLE source of sync.complete
    in Phase 12 (CONTEXT.md decision; the fetch loop in sync.py no longer
    emits it).

    MUST be called AFTER transaction.atomic() commits in _persist_success
    (RESEARCH.md anti-pattern: do not emit events from within a transaction).
    """
    from apps.reviews.services.progress import (
        read_progress_snapshot,
        write_progress_snapshot,
    )
    from apps.reviews.services.sync import emit_progress_event

    shop_id = review.shop_id
    snapshot = read_progress_snapshot(shop_id=shop_id)
    if snapshot is None:
        # No live progress modal — no WebSocket event needed (e.g. incremental sync).
        return

    enriched = int(snapshot.get("enriched", 0)) + 1
    fetched = int(snapshot.get("fetched", 0))

    new_snapshot = {**snapshot, "enriched": enriched}
    if fetched > 0 and enriched >= fetched:
        new_snapshot["status"] = "success"
    else:
        new_snapshot["status"] = "enriching"
    write_progress_snapshot(shop_id=shop_id, data=new_snapshot)

    emit_progress_event(
        shop_id=shop_id,
        payload={
            "type": "sync.enrichment.progress",
            "shop_id": shop_id,
            "enriched": enriched,
            "fetched": fetched,
        },
    )

    if fetched > 0 and enriched >= fetched:
        emit_progress_event(
            shop_id=shop_id,
            payload={
                "type": "sync.complete",
                "shop_id": shop_id,
                "total_fetched": fetched,
                "total_enriched": enriched,
                "duration_seconds": snapshot.get("duration_seconds"),
            },
        )
```
