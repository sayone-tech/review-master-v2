## Spacing Scale

Standard 8-point scale in use across the project. Phase 12 follows the same scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gap (gap-1), inline chip padding |
| sm | 8px | Chip group gap (gap-2), tight row spacing |
| md | 16px | Section horizontal padding (px-4) |
| lg | 24px | Modal content padding (px-6), section breaks |
| xl | 32px | Between major modal sections (space-y-8 where needed) |
| 2xl | 48px | Not used in Phase 12 modal contexts |
| 3xl | 64px | Not used in Phase 12 |

Exceptions:
- Progress bar height: 8px (h-2) — existing ProgressModal value, not an 8-point unit but
  consistent with Phase 11 rendering.
- Touch targets on bell button: 34×34px (w-[34px] h-[34px]) — existing TopbarBell value,
  kept for continuity.

## Component Contracts

### 1. ProgressModal — enrichment progress bar (ENRCH-14 / PROG-01 / PROG-08)

**File:** `frontend/src/widgets/review-management/ProgressModal.tsx`

**What changes in Phase 12:** The second progress bar ("Processed with AI") goes live.
In Phase 11 it was scaffolded with static copy "Will be processed after sync completes."
Phase 12 wires it to real `sync.enrichment.progress` WebSocket events.

#### Stage labels (exact copy)

| Label | Token | Value |
|-------|-------|-------|
| Fetch bar section micro-label | uppercase 12px semibold subtle | `FETCHED FROM GOOGLE` |
| Enrichment bar section micro-label | uppercase 12px semibold subtle | `PROCESSED WITH AI` |

#### Progress bar fill colours

| Bar | Fill colour | Token |
|-----|-------------|-------|
| Fetch bar | #FACC15 | `yellow` |
| Enrichment bar | #16A34A | `green` |

Both bars: track is `bg-line` (#E4E4E7), height 8px (h-2), rounded-full. Existing DOM structure
is unchanged.

#### Live counter copy (enrichment bar)

While in progress (enriched < fetched):
```
{enriched} of {fetched}
```

When fetch is complete and enrichment is still running (fetched progress bar hits 100%):
The fetch bar label area changes the sub-label text from "About N minutes left" to nothing
(eta is no longer relevant). The enrichment bar shows the live `{enriched} of {fetched}` counter.

The static "Will be processed after sync completes" sub-label under the enrichment bar is
**removed** — replaced by the live counter once any enrichment events arrive. Until the first
`sync.enrichment.progress` event is received, the sub-label reads:
```
Starting AI analysis…
```

#### sync.complete banner (CHANGED SEMANTICS in Phase 12)

The green banner with `CheckCircle` and "Sync complete" text fires only after both bars are 100%.
**The `sync.complete` WebSocket event now fires after enrichment is done**, not after fetch.

Banner copy (unchanged from Phase 11 scaffolding):
```
Sync complete
Fetched {N} reviews in {duration}s.
```

If `duration_seconds` is null: omit the "in {duration}s" fragment.

#### Snapshot type update

Add `enriching` to the `status` union (already done in Phase 11 scaffolding: `"fetching" |
"enriching" | "success" | "failed"`). Phase 12 sets `status = "enriching"` when the first
`sync.enrichment.progress` event arrives and fetch is already 100%.

#### sync.enrichment.progress event handler

When `data.type === "sync.enrichment.progress"`:
```
setSnapshot(prev => prev ? {
  ...prev,
  enriched: data.enriched,
  status: prev.fetched > 0 && data.enriched >= 0 ? "enriching" : prev.status,
  last_update_at: new Date().toISOString(),
} : null)
```

### 2. TopbarBell — enriching stage in popover (PROG-06 / PROG-08)

**File:** `frontend/src/widgets/review-management/TopbarSyncIndicator.tsx`

**What changes in Phase 12:** `sync.complete` fires later (after enrichment), so the bell keeps
shops in the `active` list through the full enrichment stage. The popover copy must distinguish
"fetching from Google" from "processing with AI."

#### Popover row copy per stage

The bell popover row for an active shop currently shows "Syncing reviews…". Phase 12 adds
stage-aware copy driven by the snapshot's `status` field received via WebSocket.

| Snapshot status | Sub-label copy | Icon |
|-----------------|----------------|------|
| `fetching` (or no snapshot yet) | `Fetching reviews from Google…` | `Loader2` size 15, animate-spin, text-yellow |
| `enriching` | `Analysing reviews with AI…` | `Loader2` size 15, animate-spin, text-green |
| `failed` | `Sync failed` | `AlertTriangle` size 15, text-red |
| `success` | `{N} review{s} synced` | `CheckCircle` size 15, text-green-500 |

The `TopbarBell` already tracks `active` shops via WebSocket. Phase 12 extends the per-shop
state to also carry `stage: "fetching" | "enriching"` derived from incoming events:
- On `sync.fetch.progress` → stage = `"fetching"`
- On `sync.enrichment.progress` → stage = `"enriching"`
- On `sync.complete` → remove from active, move to completed
- On `sync.error` → remove from active, move to failures

The pulsing yellow dot on the bell icon remains unchanged (any `active.length > 0` → yellow pulse).

### 3. Action item chips on review card (REVW-08 partial / ENRCH-14)

**File:** `frontend/src/widgets/review-management/ReviewTable.tsx`

**What changes in Phase 12:** Add a non-interactive action item count chip to the review card.
The chip renders from `extracted_action_items` on `ReviewRow`.

#### Chip specification

- Appearance: `inline-flex items-center gap-1 px-2 py-0.5 text-[12px] font-semibold rounded-full`
- Background: #FEF3C7 (`amber-tint`)
- Text colour: #D97706 (`amber`)
- Icon: `Sparkles` (lucide-react), size 12, aria-hidden
- Copy: `{N} action item` (singular) / `{N} action items` (plural)
- Not rendered when `extracted_action_items` is empty (length === 0) or null
- Not clickable in Phase 12 — no `onClick`, no `cursor-pointer`

#### Type update

Add to `ReviewRow` in `types.ts`:
```ts
extracted_action_items: Array<{
  title: string;
  scope: "shop" | "brand";
  priority: "high" | "medium" | "low";
}>;
```

Default: `[]` (serializer will always return an array).

#### Placement in the table

Action item chips appear **below the sentiment badge and tag chips** within the `"sentiment"` column.
The `SentimentBadge` component renders its own chip row. The action item chip is rendered
immediately after `SentimentBadge` in the column cell, separated by `mt-2` (8px — `sm` spacing token).

Exact cell structure for the `"sentiment"` column:
```tsx
<div className="flex flex-col gap-2">
  <SentimentBadge ... />
  {row.extracted_action_items.length > 0 && (
    <ActionItemChip count={row.extracted_action_items.length} />
  )}
</div>
```

`ActionItemChip` is a new small presentational component in the review-management widget folder.

### 4. SentimentBadge — no changes (confirmed)

`SentimentBadge.tsx` handles all three `enrichmentStatus` states correctly:
- `PENDING` / `IN_PROGRESS` → amber "Analyzing…" pill with `Loader2` spinner
- `SUCCESS` → sentiment badge + tag chips (up to 5)
- `FAILED` → `AlertCircle` icon in red, tooltip "AI analysis failed. Will retry automatically."

Phase 12 populates real data into `tags` and `sentiment` fields. The component itself is
**not modified**. The API serializer adds `extracted_action_items` to `ReviewReadSerializer`;
`SentimentBadge` remains unaware of action items.

## Interaction States

### ProgressModal state machine

| State | Fetch bar | Enrichment bar | Footer |
|-------|-----------|----------------|--------|
| Initial / no snapshot | 0% yellow | 0% green, "Starting AI analysis…" | "Run in background" (left), "View Shop Details" (disabled, right) |
| Fetching | N% yellow, live counter + ETA | 0% green, "Starting AI analysis…" | Same |
| Enriching (fetch done) | 100% yellow | M% green, live counter | Same |
| Success | 100% yellow | 100% green | CheckCircle banner; "View Shop Details" enabled |
| Failed | preserved% | preserved% | AlertTriangle banner; "View Shop Details" enabled; "Reconnect Google" if `invalid_grant` |

"Run in background" text link is hidden once `isComplete || isError`.

### Bell badge priority (unchanged from Phase 11)

1. Yellow pulsing dot — any active syncs (includes enriching stage now)
2. Red solid dot — any failures (no active)
3. Green solid dot — completed syncs awaiting dismiss (no active, no failures)
4. Red solid dot — unread notifications only (no sync activity)
