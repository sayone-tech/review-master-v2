<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller → moderate_input | Untrusted review text crosses here; must be length-capped and category-checked before flowing to OpenAI |
| moderate_output → caller | Untrusted LLM output crosses here; must be category-checked before being returned to user or persisted |
| guardrails → OpenAI Moderation API | Outbound network call; fail-open per D-24 to keep system available during API outage |
| guardrails → AiUsageLog row | Audit-row write must survive caller transaction rollback (D-33 — outside atomic()) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | Tampering (prompt injection) | moderate_input — review text path | mitigate | Length truncation to OPENAI_REVIEW_TEXT_MAX_CHARS (D-21) + structural system/user role isolation (D-05, enforced by upstream prompts.py) prevent direct prompt injection. Category check on high-severity classes (D-23, D-30) blocks the worst inputs. |
| T-20-02 | Tampering (indirect injection via long content) | moderate_input | mitigate | Hard char cap with `…[truncated]` suffix; suffix is non-instructional so a model that obeys it gains no exploit surface. |
| T-20-03 | Information Disclosure (harmful generated reply) | moderate_output | mitigate | Output text run through same Moderation API + same high-severity category set; flagged outputs are never returned (HTTP 422 via Plan 20-07). |
| T-20-04 | Denial of Service / Availability | _moderate_with_retry | mitigate | Single retry after 1s; on second failure, fail-open and log ERROR so monitoring detects sustained outages. Trade-off (brief unsafe window) documented in D-24. |
| T-20-05 | Repudiation (audit-log loss) | _persist_moderated_log | mitigate | AiUsageLog writes happen OUTSIDE any caller transaction.atomic() block (D-33). Code-level enforcement: no atomic() import in this module; grep gate in acceptance criteria. |
| T-20-06 | Information Disclosure (review text in logs) | logger.warning calls | mitigate | Only category names and entity IDs logged; review text never logged at any level (CLAUDE.md §21). Acceptance criterion enforces no review-text variable in log call sites. |
| T-20-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan; phase reuses openai SDK already in pyproject.toml. |
</threat_model>
