<objective>
Surgical backend cleanup of Phase 8 to drop the MANUAL connection method (and all its API-key machinery) plus three address subfields (city, state, zip_code) from the Shop model, serializers, services, viewset, and tests. This is a destructive removal — every reference to MANUAL/api_key/reveal_key/rotate_key/city/state/zip_code in `apps/shops/` is either deleted outright or replaced. A single Django migration `0003_remove_manual_and_address_subfields.py` performs all schema changes in one step. The plan also updates REQUIREMENTS.md and ROADMAP.md so the spec text matches the simplified contract.

Purpose: User decided in /gsd:discuss-phase follow-up that manual API-key shops are out of scope and that location data is reduced to a single Street Address line. Phase 8 backend currently still encodes both, so verification reports SATISFIED for SHOP-10/19/20 against requirements that the user has now retired. This plan brings the schema, code, AND requirement spec in line with the new product decision so future verification runs check the right truths.

Output: A backend that supports exactly two connection methods (GOOGLE_OAUTH, NOT_CONNECTED), one address field (street_address), and a ShopViewSet whose only mutating endpoints are create / partial_update / activate / deactivate / reconnect / oauth_result. REQUIREMENTS.md SHOP-03 reflects the trimmed search; SHOP-10/19/20 are explicitly marked retired. Plan 07 (frontend) consumes this contract.
