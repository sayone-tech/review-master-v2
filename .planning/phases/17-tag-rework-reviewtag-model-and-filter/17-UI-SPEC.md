## Component Inventory

### 1. Tags multi-select dropdown (`TagsFilter` in `ReviewFilters.tsx`)

**Trigger element:**
- Same visual style as existing `selectCls` selects: `px-3.5 py-[10px] border border-line rounded-[10px] text-[14px] font-medium text-ink bg-white`
- Replace the `<select>` native element with a custom button trigger (needed for multi-select behaviour)
- Active selection count badge: small `inline-flex` circle `w-4 h-4 bg-yellow text-black text-[10px] font-bold rounded-full` rendered to the right of the trigger text when ≥1 tag selected
- Chevron icon: same `ChevronIcon` component already defined in `ReviewFilters.tsx`

**Dropdown panel:**
- `position: absolute`, `z-index: 50`, `mt-1` below trigger
- `bg-white border border-line rounded-[10px] shadow-md`, width matches trigger (100%)
- Max height: `240px` with `overflow-y-auto`
- `py-1` vertical padding

**Search input inside dropdown:**
- `px-3 py-2 border-b border-line` separator below search
- Search icon `lucide-react Search` at 13px, `text-muted`
- Input: `text-[13px] font-medium text-ink placeholder:text-faint focus:outline-none bg-transparent`

**Tag option row:**
- `flex items-center justify-between px-3 py-[7px] cursor-pointer hover:bg-line-soft transition-colors`
- Left: checkbox-like check indicator (`✓` in `text-[12px] font-bold text-ink w-3` or `w-3` empty space), then tag label at `text-[13px] font-medium text-ink`
- Right: count at `text-[11px] text-faint`
- Selected row background: `bg-line-soft` (persistent, not just hover)

**Keyboard behaviour:**
- `Escape` closes dropdown, returns focus to trigger
- `Enter` / `Space` on trigger opens/closes dropdown
- `Arrow Up/Down` navigates options
- `Enter` on option toggles selection
- Tab closes dropdown and moves to next focusable element

**ARIA:**
- Trigger: `role="combobox"`, `aria-haspopup="listbox"`, `aria-expanded={open}`, `aria-label="Filter by tag"`
- Panel: `role="listbox"`, `aria-multiselectable="true"`, `aria-label="Tags"`
- Each option: `role="option"`, `aria-selected={selected}`

### 2. Clickable tag chips (`ReviewTable.tsx`)

Current chips are `<span>` elements. Upgrade to `<button type="button">`.

**Visual spec (chip as button):**
- Identical to current static chip: `inline-flex items-center px-1.5 py-0.5 text-[11px] font-medium rounded` with `TAG_STYLES[polarity]`
- Add `cursor-pointer` (already a button so inherits)
- Add hover: slight opacity drop — `hover:opacity-80 transition-opacity`
- Add `focus-visible:ring-1 focus-visible:ring-ink focus-visible:ring-offset-1 focus-visible:outline-none` for keyboard accessibility

**Interaction:**
- `onClick`: calls a new `onTagClick(label: string)` prop passed down from `ReviewManagementWidget`
- `onTagClick` adds the tag label to the active tags filter array (additive, AND semantics)
- If the tag is already in the active filter, clicking it again removes it (toggle)
- `aria-label="Filter by {label}"` on each chip button
- `aria-pressed={isActive}` where `isActive = activeTags.includes(tag.label)`

### 3. Filter state additions (`ReviewFilterParams`)

New field added to `ReviewFilterParams` in `types.ts`:

```typescript
tags?: string[];   // comma-joined as ?tags=Cleanliness,Wait+Time on the wire
```

The `buildQs()` function in `api.ts` serialises: `u.set("tags", tags.join(","))`.

### 4. Loading state for tag list endpoint

A single `useQuery`-style fetch at component mount (or when `shop` filter changes). While loading:
- Dropdown trigger is disabled: `opacity-50 cursor-not-allowed pointer-events-none`
- No skeleton needed — trigger text shows "Tags" and chevron remains visible

On error: trigger remains enabled but dropdown shows the error copy defined above.

## Filter Panel Layout Change

The existing filter panel has two rows in a CSS grid. The Tags filter is added to **Row 1** as a 5th column, replacing the current 4-column layout:

**Row 1 (updated):**
```
gridTemplateColumns: "minmax(0,1.6fr) minmax(0,1fr) minmax(0,1fr) minmax(0,1fr) minmax(0,1fr)"
```
Columns: Search | Store | Rating | Sentiment | Tags

This keeps the panel within a single scrollable row at desktop widths (>1024px). At narrower viewports the grid wraps — no change to existing responsive behaviour.

## Interaction States

| State | Behaviour |
|-------|-----------|
| Tags dropdown closed, 0 selected | Trigger shows "Any tag" |
| Tags dropdown closed, 1 selected | Trigger shows the label, yellow badge with "1" |
| Tags dropdown closed, N selected | Trigger shows "{N} tags", yellow badge with "{N}" |
| User opens dropdown | Panel appears, search input auto-focused |
| User types in search | Tag list filters client-side (no additional API call) |
| User clicks option | Checkmark appears, row stays highlighted; list does not close |
| User clicks outside or presses Escape | Dropdown closes, selection preserved |
| User clicks Apply button | `onApply` called with draft including `tags: string[]` |
| User clicks Reset | Tags filter cleared; trigger returns to "Any tag" |
| User clicks tag chip in table | Tag label added/toggled in active tags filter; list re-fetches immediately (bypasses draft — direct apply) |

Note: chip click applies immediately (no Apply button required), matching the mental model of "clicking to explore." The filter panel draft state is updated to reflect the chip-applied tag so the Apply button remains coherent.
