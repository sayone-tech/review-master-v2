  <action>
    In apps/reviews/filters.py, in the ReviewFilterSet class body:
    - Add after the last existing filter field declaration: `tags = django_filters.CharFilter(field_name="", method="filter_tags")`
    - Use `field_name=""` (empty string) to prevent django-filter from attempting to resolve "tags" as a model field — after removing the JSONField, "tags" is a RelatedManager and auto-resolution would fail (per Open Question 3 in RESEARCH.md).

    Add the filter_tags method on ReviewFilterSet (after the last existing method):
    - Signature: `def filter_tags(self, queryset, name, value):`  # type: ignore[no-untyped-def]
    - If not value: return queryset
    - tag_labels = [t.strip() for t in value.split(",") if t.strip()]
    - Chain: for label in tag_labels: queryset = queryset.filter(tags__label__iexact=label)
    - Return: queryset.distinct()

    The .distinct() is mandatory — chained reverse FK joins produce duplicate rows when a review has multiple ReviewTag rows. Without it, pagination counts are inflated (Pitfall 5 in RESEARCH.md).

    Also add `tags` to the FilterSet's Meta.fields list (or the explicit fields dict) if ReviewFilterSet uses a Meta.fields declaration — check the existing structure first. If it uses field-level declarations only (no Meta.fields list), no change needed.
