## Component Specification: Review History Field

This section is the primary deliverable for Phase 16. It is prescriptive and actionable.

### Placement in Step 3

Step 3 field order (top to bottom):
1. Non-field error banner (conditional)
2. Connected listing pill (green, read-only)
3. Shop Name (text input)
4. Region (select) — existing
5. **Review History (select) — NEW, conditional on `allowCustomSyncDepth === true`**
6. Phone (text input, optional)
7. Street Address (text input)
8. Footer (Cancel / Add Shop)

Source: D-07 — "after Region, before Phone."

### Conditional Render Rule

```
{allowCustomSyncDepth && (
  <div>
    {/* Review History field */}
  </div>
)}
```

When `allowCustomSyncDepth` is `false`, the entire `<div>` is absent from the DOM — not
hidden via CSS, not disabled. React conditional rendering: `{condition && <element>}`.

Source: D-10 and the `<specifics>` block in CONTEXT.md.

### Field Structure (exact Tailwind classes)

The Review History field replicates the Region select (lines 432–455 of `CreateShopModal.tsx`)
with these differences: different `htmlFor`/`id`, different label text, no error state
(field always has a valid default), and the addition of a helper text line.

```
<div>
  <label htmlFor="cs-sync-depth" className={labelCls}>
    Review History
  </label>
  <p className="mt-1 text-[12px] text-muted">
    Sets how far back this shop's initial review sync will go.
  </p>
  <select
    id="cs-sync-depth"
    value={syncDepth}
    onChange={(e) => setSyncDepth(e.target.value as SyncDepth)}
    className={inputCls}
    aria-label="Review History"
  >
    <option value="ONE_YEAR">Last 1 year</option>
    <option value="TWO_YEARS">Last 2 years</option>
    <option value="ALL_TIME">All time</option>
  </select>
</div>
```

Key contract points:
- `labelCls` applied unchanged: `block text-[12px] font-semibold text-subtle tracking-[0.05em] uppercase mb-1`
- `inputCls` applied unchanged: `w-full px-3 py-2 text-[13.5px] bg-white border border-line rounded-md focus:outline-none focus:ring focus:ring-black/[0.06] focus:border-ink`
- Helper text `<p>` uses `mt-1 text-[12px] text-muted` — same pattern as helper texts elsewhere in the codebase
- Helper text renders between the label and the select (label → helper → select)
- No `inputErrorCls` variant for this field; the select always has a valid value (default prevents blank)
- No validation error display — the field is pre-populated with a valid default at mount

Source: D-08, D-09; structure validated against existing Region select in `CreateShopModal.tsx`.

### State Initialization

```
const [syncDepth, setSyncDepth] = useState<SyncDepth>("TWO_YEARS");
```

Initialized to `"TWO_YEARS"` (string literal matching `Shop.SyncDepth.TWO_YEARS`).
Reset to `"TWO_YEARS"` inside the `reset()` function.

Source: D-10. `SyncDepth` type already exists in `types.ts` as `"ONE_YEAR" | "TWO_YEARS" | "ALL_TIME"`.

### Payload Field

`sync_depth` is included in `ShopCreatePayload` only when `allowCustomSyncDepth` is true.
Two acceptable implementation patterns:
1. Always include `sync_depth` in the payload (backend accepts it regardless per D-05).
2. Conditionally include: `...(allowCustomSyncDepth ? { sync_depth: syncDepth } : {})`.

Either is valid; the visual contract is unaffected. Executor may choose based on simplicity.

## Bootstrap Tag Contract

### Template addition to `templates/shops/shop_list.html`

New `json_script` tag placed immediately after the existing `shop-regions-data` tag
(line 31 of the current template):

```
{{ allow_custom_sync_depth|json_script:"shop-org-data" }}
```

Where `allow_custom_sync_depth` is a boolean context variable (`True`/`False`) passed by
the `shop_list` view.

Django's `json_script` filter renders this as:
```html
<script id="shop-org-data" type="application/json">true</script>
```

### Entrypoint read (`shop-management.tsx`)

```
const orgData = parseJson<{ allow_custom_sync_depth: boolean }>(
  "shop-org-data",
  { allow_custom_sync_depth: false },
);
```

Fallback is `false` — if the tag is missing or parsing fails, the dropdown is absent (safe
default: system default depth is TWO_YEARS per SDEP-02).

Source: D-01, D-02, D-03.

## Accessibility Contract

- `<label htmlFor="cs-sync-depth">` paired with `<select id="cs-sync-depth">` — label association is explicit.
- `aria-label="Review History"` on the `<select>` as a redundant accessible name (consistent with Region select pattern in the same form).
- The field is only rendered when meaningful (when `allowCustomSyncDepth` is true), so screen readers do not encounter a disabled or hidden field — it is simply absent.
- No additional ARIA attributes required. The select element's native semantics are sufficient.
