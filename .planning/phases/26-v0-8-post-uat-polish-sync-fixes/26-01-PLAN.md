## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Org/Staff user → OrgCanonicalTagViewSet (search) | Untrusted `search` query param crosses into a tenant-scoped list query |
| Celery scheduler → fetch_and_persist_reviews | Trigger value decides whether progress state (per-shop Redis snapshot) is written |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-01 | Information Disclosure | OrgCanonicalTagViewSet search | mitigate | `search` composes with the existing `organisation_id` filter in `list_canonical_tags_for_org`; the org-scope filter is applied unconditionally and is never replaced by search. Selector test asserts a same-label tag in another org is excluded. `IsOrgAdmin` stays on the viewset. |
| T-26-02 | Tampering | `search` query param | mitigate | Only the explicit `label__icontains` lookup is exposed — no arbitrary `__` lookups (§8). DRF parameterises the value (ORM-bound), so no SQL injection surface. |
| T-26-03 | Denial of Service | search query cost | accept | Search runs on the same `organisation_id`-filtered queryset with the existing query-count ceiling (≤2, asserted by test); `label__icontains` is a bounded scan on the per-org tag set (small cardinality). |
| T-26-04 | Tampering | progress snapshot (per-shop Redis) | mitigate | Snapshot writes/clears/emits gated on `trigger == "initial"` so an overlapping incremental can no longer reset another flow's modal; gate is per-shop scoped (no cross-shop write). Regression test enforces 0 writes for incremental. |
| T-26-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages introduced in this plan (no install tasks). |
</threat_model>
