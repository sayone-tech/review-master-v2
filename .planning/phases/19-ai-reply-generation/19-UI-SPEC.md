# Phase 19 — UI Design Contract: AI Reply Generation

> Visual and interaction contract for the "Generate with AI" feature in ReplyComposer.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — manual Tailwind CSS only |
| Icon library | lucide-react (already installed — use `Loader2`, `Sparkles`) |
| Font | Geist (already loaded via tailwind.config.js `fontFamily.sans`) |

No new npm packages. No shadcn. No Radix. All styling via Tailwind utility classes using the token palette in `frontend/tailwind.config.js`.

---

## Spacing Scale

Declared values (all multiples of 4px — 8-point grid):

| Token | Value | Tailwind class | Usage |
|-------|-------|----------------|-------|
| xs | 4px | gap-1, p-1 | Icon-to-text gap inside pill |
| sm | 8px | gap-2, px-2, py-2 | Gap between pills; pill vertical padding |
| md | 16px | px-4, py-4 | Composer container horizontal padding (inherited) |
| lg | 24px | mt-6 | (not used in this feature) |

Exceptions:
- Pre-existing in ReplyComposer: `px-2.5 py-1` on "Use template" button (10px / 4px — DO NOT change this element). The new "Generate with AI" button must NOT copy these non-grid values; use `px-2 py-1` (8px / 4px) instead.
- Pre-existing: `mt-0.5` on some text elements in the replied view — not touched by this phase.

New elements introduced by this phase must use only grid-compliant spacing: `px-2 py-1`, `gap-1`, `gap-2`, `mt-2`, `px-4 py-2`.

## Typography

All sizes are multiples of 4px. Max 4 sizes, max 2 weights.

| Role | Size | Tailwind | Weight | Tailwind | Line Height | Usage |
|------|------|----------|--------|----------|-------------|-------|
| Body / textarea | 14px | text-[14px] | normal (400) | font-normal | 1.5 | Textarea text, generated draft |
| Label / button | 12px | text-[12px] | semibold (600) | font-semibold | 1.4 | "Generate with AI" button, pill labels, confirmation text, error text |
| (Pre-existing) Primary action | 14px | text-[14px] | semibold (600) | font-semibold | n/a | "Submit Reply", "Discard Reply" — not changed |
| (Pre-existing) Section label | 12px | text-[12px] | semibold (600) | font-semibold | n/a | "YOUR REPLY" label — not changed |

**Prohibited in this phase:** `font-medium`, `text-[13px]`, `text-[13.5px]`, `text-[11.5px]`, `text-[15px]`, any non-4-multiple px size.

Note: The pre-existing "Use template" button uses `font-medium` — do not replicate that weight on new elements.

**Pre-existing exception — `text-[14px]` on new elements:** The generated draft fills into the existing textarea (ReplyComposer.tsx line ~273) and the error row reuses the existing `errorMessage` container. Both already use `text-[14px]`. New elements that render into or alongside those containers must match this size for visual consistency. This is an inherited value from the pre-existing component, not a new design choice.

## Component Anatomy

### 1. Toolbar row (modified)

**Current structure:**
```
<div className="flex items-center justify-between mb-2">
  <label …>YOUR REPLY</label>
  {templates.length > 0 && <div ref={pickerRef}> … Use template … </div>}
</div>
```

**New structure:**
```
<div className="flex items-center justify-between mb-2">
  <label …>YOUR REPLY</label>
  <div className="flex items-center gap-2">          ← new wrapper
    <GenerateWithAiButton />                          ← new element, left
    {templates.length > 0 && <TemplatePicker />}     ← existing, right
  </div>
</div>
```

### 2. "Generate with AI" button

```tsx
<button
  type="button"
  aria-label="Generate reply with AI"
  aria-expanded={generatorOpen}
  aria-controls={`ai-generator-${row.id}`}
  onClick={handleToggleGenerator}
  className="inline-flex items-center gap-1 px-2 py-1 text-[12px] font-semibold border border-line rounded-md text-ink bg-white hover:bg-line-soft transition-colors"
>
  <Sparkles size={12} aria-hidden="true" />
  Generate with AI
</button>
```

- Size: Sparkles icon at 12px matches ChevronDown on the "Use template" button.
- `py-1` = 4px top/bottom. `px-2` = 8px left/right. Both are 4px-grid-compliant.
- `gap-1` = 4px between icon and label.
- When `generatorOpen === true`: add `bg-line-soft` to background (visually depressed). No separate "active" class needed — just swap bg in the className expression.

### 3. Pill row (generatorOpen=true, textarea IS empty)

Rendered immediately below the label row, above the textarea, using a new `<div id={...}>`:

```tsx
<div
  id={`ai-generator-${row.id}`}
  className="flex items-center gap-2 mb-2"
  role="group"
  aria-label="Select tone for AI reply"
>
  <TonePill tone="professional" />
  <TonePill tone="friendly" />
</div>
```

### 4. Tone pill (idle state)

```tsx
<button
  type="button"
  onClick={() => handleGenerate("professional")}
  disabled={generatingTone !== null}
  aria-busy={generatingTone === "professional"}
  aria-label="Generate Professional reply"
  className="inline-flex items-center gap-1 px-2 py-1 text-[12px] font-semibold border border-line rounded-md bg-white text-ink hover:bg-amber-tint hover:text-amber hover:border-amber transition-colors disabled:opacity-50 disabled:cursor-not-allowed disabled:hover:bg-white disabled:hover:text-ink disabled:hover:border-line"
>
  Professional
</button>
```

Same structure for "Friendly".

### 5. Tone pill (loading state — this specific tone is generating)

```tsx
<button
  type="button"
  disabled
  aria-busy="true"
  aria-label="Generating Professional reply…"
  className="inline-flex items-center gap-1 px-2 py-1 text-[12px] font-semibold border border-line rounded-md bg-line-soft text-faint cursor-not-allowed"
>
  <Loader2 size={12} className="animate-spin text-amber" aria-hidden="true" />
  Professional…
</button>
```

`Loader2` from lucide-react with `animate-spin` — already available, no new imports beyond what is needed.

### 6. Confirmation row (generatorOpen=true, textarea IS NOT empty)

Replaces the plain pill row. Rendered in the same `id={`ai-generator-${row.id}`}` container:

```tsx
<div
  id={`ai-generator-${row.id}`}
  className="flex items-center gap-2 mb-2 flex-wrap"
  role="group"
  aria-label="Confirm replacing draft with AI reply"
>
  <span className="text-[12px] text-muted">Replace your draft with AI reply?</span>
  <TonePill tone="professional" />   {/* doubles as confirm action */}
  <TonePill tone="friendly" />
  <button
    type="button"
    onClick={handleCancelGenerator}
    className="text-[12px] font-semibold text-muted hover:text-ink transition-colors"
    aria-label="Cancel AI reply generation"
  >
    Cancel
  </button>
</div>
```

The pill buttons here call `handleGenerate(tone)` — same handler, which overwrites the textarea on success. The confirmation text makes the destructive intent clear without a separate modal.

### 7. Error row (post-generation API failure)

Rendered in the **existing** `errorMessage` slot below the textarea. Identical to submit errors:

```tsx
{errorMessage && (
  <div
    role="alert"
    className="border-l-4 border-red bg-red-tint px-4 py-2 text-[14px] text-red rounded-sm mt-2"
  >
    {errorMessage}
  </div>
)}
```

No new error container — the generator uses the same `errorMessage` state variable already in `ReplyComposer`. On generation error, `setErrorMessage(...)` is called, pills collapse (`setGeneratorOpen(false)`, `setGeneratingTone(null)`).

All strings are exact. No variants, no ellipsis alternatives.

| Element | Exact Copy | Notes |
|---------|-----------|-------|
| Generator button label | `Generate with AI` | No "▾" chevron — the expand is inline, not a dropdown |
| Pill label — Professional | `Professional` | Title case |
| Pill label — Friendly | `Friendly` | Title case |
| Pill label — loading (Professional) | `Professional…` | Ellipsis U+2026, not three dots |
| Pill label — loading (Friendly) | `Friendly…` | Same |
| Confirmation prompt | `Replace your draft with AI reply?` | No colon. Space before pills. |
| Cancel button | `Cancel` | Not "Dismiss", not "No thanks" |
| Error — AI unavailable | `AI generation failed. Please try again or write your reply manually.` | Matches D-17 backend error detail verbatim |
| Error — rate limited (429) | `You've reached the AI generation limit. Please wait a moment.` | Mirrors existing rate-limit copy pattern in submit handler |
| `aria-label` — generator button (closed) | `Generate reply with AI` | Includes "reply" for context |
| `aria-label` — generator button (open) | `Generate reply with AI` | Same — expanded state communicated via `aria-expanded` |
| `aria-label` — Professional pill | `Generate Professional reply` | |
| `aria-label` — Friendly pill | `Generate Friendly reply` | |
| `aria-label` — Professional pill (loading) | `Generating Professional reply…` | |
| `aria-label` — Friendly pill (loading) | `Generating Friendly reply…` | |
| `aria-label` — Cancel button | `Cancel AI reply generation` | |

## Interaction State Machine

States are encoded in two React state variables added to `ReplyComposer`:

```ts
const [generatorOpen, setGeneratorOpen] = useState(false);
const [generatingTone, setGeneratingTone] = useState<"professional" | "friendly" | null>(null);
```

| State | `generatorOpen` | `generatingTone` | What is visible |
|-------|----------------|-----------------|-----------------|
| idle | false | null | Generator button only (no pills) |
| expanded-empty | true | null | Pill row (plain pills, no confirmation text) |
| expanded-nonempty | true | null | Pill row with confirmation text + Cancel |
| loading | true | "professional" \| "friendly" | Both pills disabled; active pill shows spinner + "…" label |
| success | false | null | Pills collapse; textarea filled; focus on textarea |
| error | false | null | Pills collapse; errorMessage set; generator button available again |

### Transition rules

```
idle
  → [click Generate button] → expanded-empty   (if textarea.trim() === "")
  → [click Generate button] → expanded-nonempty (if textarea.trim() !== "")

expanded-*
  → [click Generate button again] → idle        (toggle closed)
  → [click Cancel] → idle                        (Cancel only available in expanded-nonempty)
  → [click a tone pill] → loading

loading
  → [API 200] → success
  → [API error] → error

success
  → idle                                          (automatic on success)

error
  → idle                                          (automatic on error, errorMessage set)
  → [click Generate button] → expanded-* again   (user can retry)
```

### Focus management

- On success: call `document.getElementById(`reply-textarea-${row.id}`)?.focus()` after setting textarea value. This matches the pattern used when a template is selected (which calls `setComment(t.content)` and closes the picker — focus stays implicit there, but for AI generation an explicit focus is warranted since the action is modal/loading-based).
- On error: focus returns to the generator button. Call `ref.current?.focus()` on the generator button element. Requires adding a `useRef<HTMLButtonElement>(null)` for the generator button.
- On Cancel: focus returns to the generator button (same ref).
