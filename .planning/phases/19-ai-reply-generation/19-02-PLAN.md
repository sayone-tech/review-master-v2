    @action(
        detail=True,
        methods=["post"],
        url_path="generate-reply",
        throttle_classes=[ScopedRateThrottle],
    )
    def generate_reply(self, request: Request, pk: int | None = None) -> Response:
        """POST: generate an AI draft reply for the given review.

        Returns 200 {draft: str} on success.
        Returns 400 on invalid tone.
        Returns 502 on OpenAI failure (transient or permanent).
        D-09, D-10, D-11, D-12, D-13, D-17, D-18.
        """
        self.throttle_scope = "generate_reply"
        review = self.get_object()
        serializer = GenerateReplySerializer(data=request.data)
        serializer.is_valid(raise_exception=True)
        tone: str = serializer.validated_data["tone"]
        try:
            draft = generate_reply_draft(review=review, tone=tone)
        except (OpenAITransientError, OpenAIPermanentError, Exception) as exc:
            logger.warning(
                "generate_reply_failed review_id=%s tone=%s exc_type=%s exc=%s",
                review.pk,
                tone,
                type(exc).__name__,
                exc,
            )
            return Response(
                {
                    "code": "ai_unavailable",
                    "detail": "AI generation failed. Please try again or write your reply manually.",
                },
                status=status.HTTP_502_BAD_GATEWAY,
            )
        return Response({"draft": draft}, status=status.HTTP_200_OK)

    Note: the bare except clause catches Exception broadly because D-17 says all errors (transient, permanent, network) map to 502. Ruff rule S110 does not apply when re-raising is not the intent and the broad catch is intentional. Add "# noqa: BLE001" to the except line if ruff raises BLE001 (blind exception).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/v1/reviews/{id}/generate-reply/ | User-supplied "tone" value enters the API; review ID in URL is user-supplied |
| view → generate_reply_draft | Service receives a Review ORM object (not user input) and a validated tone string |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-04 | Spoofing | generate_reply action | mitigate | IsOrgScoped permission (inherited from ReviewViewSet) enforces tenant scoping; get_object() enforces the user can access this specific review; no extra permission class needed per D-13 |
| T-19-05 | Denial of Service | generate_reply action | mitigate | ScopedRateThrottle at "generate_reply": "10/minute" per D-12; each OpenAI call is synchronous and ≤3s, so 10/min prevents runaway cost |
| T-19-06 | Information Disclosure | 502 error response | mitigate | Error response returns generic code="ai_unavailable" and fixed detail string per D-17; no OpenAI error details, no review content, no internal stack traces exposed |
| T-19-07 | Elevation of Privilege | Staff Admin scope | mitigate | get_object() uses get_queryset() which applies get_accessible_shop_ids filtering for STAFF_ADMIN — Staff cannot reach reviews outside their scope via this endpoint |
| T-19-SC | Tampering | npm/pip/cargo installs | accept | no new packages in this plan |
</threat_model>
