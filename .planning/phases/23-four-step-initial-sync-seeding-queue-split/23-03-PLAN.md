<objective>
Wire the four-step initial sync orchestration (SEED-01/02/03), route daily
incremental enrichment to `ai-enrichment-low` (DSYNC-01), gate every OpenAI call
through the global token bucket, and move `sync.complete` ownership from the
enrichment progress emitter to the finalising pass. Apply the queue split at all
enrichment dispatch sites (QUEUE-01).

Purpose: This is the orchestration layer that ties Plan 01 (queues, token bucket)
and Plan 02 (finalising task) into the user-visible four-step flow. It is the last
backend wave because it depends on both the finalising task and the settings/Redis
helpers existing.
Output: Restructured `sync.py`, gated `enrichment.py`, queue-routed `tasks.py`,
extended sync/task tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Celery worker → OpenAI | Parallel bulk enrichment can burst past OpenAI TPM limits without a cross-worker gate |
| Service → WebSocket | Progress events broadcast to the SyncProgressConsumer group; emitting pre-commit would leak rolled-back state |
| Seed loop → DB | Sequential enrichment mutating canonical vocabulary one review at a time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-06 | Denial of Service | parallel bulk → OpenAI 429 | mitigate | Global `rate:openai:org` token bucket gates every enrich_review call (service-level, both seed and bulk); depleted → retriable raise, not a worker block (RESEARCH Pattern 1) |
| T-23-07 | Tampering | token-bucket bypass via direct call | mitigate | Guard lives in enrich_review service body, so the seed loop's direct call is gated too, not only the task wrapper (Security Domain) |
| T-23-08 | Information Disclosure | progress event for rolled-back state | mitigate | All sync.vocab/enrichment events emitted AFTER transaction.atomic() commits (Pitfall 7); no emit inside a txn |
| T-23-09 | Information Disclosure | cross-tenant snapshot leak via consumer | accept | SyncProgressConsumer auth/tenant-scoping unchanged (23-UI-SPEC §What Does NOT Change); snapshot is per-shop keyed; no new consumer or auth path introduced |
| T-23-SC | Tampering | npm/pip installs | accept | No new packages this phase (RESEARCH.md audit N/A) |
</threat_model>
