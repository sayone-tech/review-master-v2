<objective>
Wire the four-step initial sync orchestration (SEED-01/02/03), route daily
incremental enrichment to `ai-enrichment-low` (DSYNC-01), gate every OpenAI call
through the global token bucket (seed path WAITs, bulk path RAISEs), move
`sync.complete` ownership from the enrichment progress emitter to the finalising
pass, and confirm the reconnect snapshot carries the 4-step `step`/counter fields
(SEED-01). Apply the queue split at all enrichment dispatch sites (QUEUE-01).

Purpose: This is the orchestration layer that ties Plan 01 (queues, token bucket,
`_wait_for_openai_token`) and Plan 02 (finalising task) into the user-visible
four-step flow. It is the last backend wave because it depends on both the
finalising task and the settings/Redis helpers existing. It also owns the snapshot
writes for the vocab/enriching/finalising steps, so it is the right place to verify
the reconnect snapshot path end to end.
Output: Restructured `sync.py`, gated `enrichment.py`, confirmed `sync_progress.py`,
queue-routed `tasks.py`, extended sync/task/consumer/progress tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
