## Component Inventory — Four-Step ProgressModal

### Step States

Each of the four steps has four possible states. These are local UI states derived
from the incoming WebSocket event type and the `snapshot.step` discriminator.

| State | Visual |
|-------|--------|
| `pending` | Eyebrow label in `subtle`, counter shows "–", bar track only (no fill), no hint text |
| `active` | Eyebrow label in `ink`, animated fill bar, counter shows live X/Y counts, hint text if applicable |
| `complete` | Eyebrow label in `ink`, bar filled to 100%, counter shows final X count, no hint text |
| `error` | Step is replaced by the unified error block (existing pattern) — no per-step error indicator |

### The Four Steps (verbatim labels from ROADMAP SC #1 and CONTEXT.md specifics)

| Step | Label | Bar color | Event type(s) | Counter format |
|------|-------|-----------|---------------|----------------|
| 1 | Fetching Reviews | `yellow` | `sync.fetch.progress` | "{fetched} of ~{total}" (determinate) or "{fetched} fetched" (indeterminate) |
| 2 | Building Tag Vocabulary | `green` | `sync.vocab.progress` | "Building vocabulary {enriched}/{seed_total}" |
| 3 | AI Enrichment | `green` | `sync.enrichment.progress` | "Enriching {enriched}/{fetched}" |
| 4 | Finalising | `amber` | `sync.finalising.progress` | "Finalising {processed}/{total}" |

Step 1 is the existing fetch section (unchanged bar logic). Steps 2–4 are new.

### Pending Steps Visual

Steps that have not yet started render as:
- Eyebrow label: `text-[12px] font-semibold text-subtle uppercase tracking-[0.05em]`
- Counter row: `text-[14px] text-muted` showing "–"
- Progress bar: track only (`bg-line`), no fill, no animation — `opacity-60`
- No hint text below bar

This makes the full four-step roadmap visible from the moment the modal opens, even
before the first event arrives.

### Active Step Visual

Active step matches the existing section pattern:
- Eyebrow label: `text-[12px] font-semibold text-subtle uppercase tracking-[0.05em]`
- Counter row: `text-[14px] font-semibold text-ink`
- Progress bar: determinate fill (`transition-all`) when total is known; `animate-pulse` indeterminate (`w-1/3`) when total is null
- ARIA: `role="progressbar" aria-valuenow aria-valuemin=0 aria-valuemax=100 aria-label="{step}: {pct}%"`
- Hint text: `text-[12px] text-muted mt-1` when applicable (e.g. "Starting AI analysis…" for step 3 when enriched === 0)

### Complete Step Visual

- Counter row shows final total: e.g. "50 reviews" (step 1), "50 built" (step 2), "520 enriched" (step 3), "Done" (step 4)
- Bar filled to 100%
- No animation

### Step Spacing

```
<div className="space-y-5">        {/* 20px gap between step blocks */}
  {/* step block */}
  <div>
    <label className="text-[12px] font-semibold text-subtle uppercase tracking-[0.05em]">
      {stepLabel}
    </label>
    <div className="text-[14px] font-semibold text-ink mt-1">
      {counterText}
    </div>
    <div className="w-full h-2 bg-line rounded-full overflow-hidden mt-2" role="progressbar" ...>
      <div className="h-full bg-{color} rounded-full transition-all" style={{ width: `{pct}%` }} />
    </div>
    {hintText && <div className="text-[12px] text-muted mt-1">{hintText}</div>}
  </div>
</div>
```

### TypeScript Interface Extension

The existing `SnapshotState` interface must be extended. New fields added to
`ProgressModal.tsx`:

```typescript
// Additions to SnapshotState (source: CONTEXT.md D-02)
step: "fetching" | "vocab" | "enriching" | "finalising" | "success" | "failed";
vocab_enriched?: number;       // reviews processed in seed/vocab phase
vocab_total?: number;          // seed phase size (SEED_PHASE_SIZE, default 50)
finalising_processed?: number; // reviews processed in finalising pass
finalising_total?: number;     // total reviews to finalise
```

New event handler cases to add in `ws.onmessage`:

| Event type | Action |
|------------|--------|
| `sync.vocab.progress` | Set `step: "vocab"`, update `vocab_enriched`, `vocab_total` |
| `sync.enrichment.progress` | Set `step: "enriching"`, update `enriched` (existing field) |
| `sync.finalising.progress` | Set `step: "finalising"`, update `finalising_processed`, `finalising_total` |
| `sync.fetch.progress` | Set `step: "fetching"` — existing handling unchanged |
| `sync.complete` | Set `step: "success"` — existing handling unchanged |
| `sync.error` | Set `step: "failed"` — existing handling unchanged |

Initial snapshot from `consumer.connect` also carries `step` — modal renders correct
initial state without waiting for the next event.

### TopbarSyncIndicator Extension

`TopbarBell` (TopbarSyncIndicator) renders a sub-label per active shop. The current
sub-labels are "Fetching reviews from Google…" and "Analysing reviews with AI…".
Extend to four:

| Step value | Sub-label text |
|------------|----------------|
| `fetching` | "Fetching reviews from Google…" |
| `vocab` | "Building tag vocabulary…" |
| `enriching` | "Analysing reviews with AI…" |
| `finalising` | "Finalising…" |

The spinner icon color is currently `text-yellow` for fetching, `text-green` for
enriching. Extended pattern:

| Step | Spinner color |
|------|--------------|
| `fetching` | `text-yellow` |
| `vocab` | `text-green` |
| `enriching` | `text-green` |
| `finalising` | `text-amber` |

The `SyncingShop.stage` field must be extended from `"fetching" | "enriching"` to
`"fetching" | "vocab" | "enriching" | "finalising"`.

## WebSocket Event Payload Contract

Following CLAUDE.md §13.5 conventions. All events are JSON with a `type` discriminator.

| Event | New in Phase 23? | Payload Fields |
|-------|-----------------|----------------|
| `sync.fetch.progress` | No (existing) | `shop_id, fetched, total_estimate` |
| `sync.vocab.progress` | YES | `shop_id, enriched, total` — `enriched` = reviews through vocab phase so far, `total` = seed phase size |
| `sync.enrichment.progress` | No (existing, reused for bulk phase) | `shop_id, enriched, fetched` |
| `sync.finalising.progress` | YES | `shop_id, processed, total` — `processed` = reviews resolved in finalising pass, `total` = total to process |
| `sync.complete` | No (existing) | `shop_id, total_fetched, total_enriched, duration_seconds` |
| `sync.error` | No (existing) | `shop_id, stage, error_code, error_message` |

Redis snapshot at `sync:progress:{shop_id}` must carry the `step` discriminator and
all step-specific counters so the `consumer.connect` snapshot paint is correct on
reconnect.

## Accessibility Contract

- Each progress bar: `role="progressbar" aria-valuenow aria-valuemin=0 aria-valuemax=100 aria-label="{stepName}: {pct}%"`. When indeterminate (total unknown): omit `aria-valuenow` and `aria-valuemax`.
- Pending bars: `aria-label="{stepName}: not started"`, no `aria-valuenow`.
- `aria-live="polite"` region wrapping the four-step block so screen readers announce step transitions.
- Focus trap on modal open (existing `FocusTrap` — unchanged).
- Color is not the only differentiator for step state — the counter text and hint text provide textual equivalents.
