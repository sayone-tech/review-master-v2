<objective>
Deliver the two backend halves of Phase 27:

1. **SYNC-REL-01 (backend):** A versioned, org+shop-scoped GET endpoint that returns the
   current `sync:progress:{shop_id}` Redis snapshot so the ProgressModal can poll it as a
   fallback when WebSocket events are missed (the frontend half is Plan 02).
2. **SYNC-REL-02 (full):** Replace the fixed-countdown dispatch of `finalize_canonical_tags_task`
   with completion-gating — the task self-reschedules (short countdown, bounded) while any of
   the shop's reviews are still PENDING/IN_PROGRESS, then runs once all are terminal.

Purpose: A missed WebSocket event must no longer freeze the modal (the endpoint is the
fallback source of truth), and Finalising must fire promptly when bulk enrichment actually
completes — not after a multi-minute fixed guess — and be visible in the modal.

Output: A throttled `/api/v1/` GET view + URL, a bounded self-reschedule gate in the finalise
service/task, a cleaned-up Phase 4 dispatch in sync.py, and tests (cross-tenant + finalise-gating).
</objective>

| Celery beat/worker → finalize self-reschedule | Internal; per-org locked, org derived from the job (no cross-tenant surface) |
