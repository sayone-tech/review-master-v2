# Phase 25 — UI Design Contract

> Visual and interaction contract for Phase 25: Org Admin Tag Management & Dashboard Polarity.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** Five UI surfaces — all Org-Admin-only, Staff cannot reach any of them.
> 1. Tags page (`/admin/org/tags/`) — sortable paginated data table
> 2. Inline rename — edit label in-place in the table row
> 3. Merge modal — searchable target picker + irreversibility warning
> 4. Merge progress — HTTP-polled in-progress bar + completion toast + failure path
> 5. Dashboard polarity — extend existing tag chart with stacked mixed-polarity split
>
> **Primary focal point:** The tag data table card on the Tags page — it spans the full
> content width and is the only interactive surface on the page. All other surfaces
> (rename input, merge modal, progress banner) are overlaid on or adjacent to this card.

## Spacing Scale

Matches the existing platform scale (multiples of 4). Token `12px` (gap-3 / px-3 / py-3)
is added explicitly because it appears in multiple surfaces in this phase.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-text gap in polarity badge; rename input side padding |
| sm | 8px | Gap between table header and filter row; badge internal padding; tooltip dot margin (`mr-2`) |
| — | 12px | Modal inner section gap (`py-3`); footer divider top padding (`pt-3`); section heading bottom margin (`mb-3`) |
| md | 16px | Table cell horizontal padding (inherits `px-4` from DataTable); modal section gap |
| lg | 24px | Modal `px-6` horizontal padding (inherited from `Modal.tsx`); page heading bottom margin |
| xl | 32px | Page-level section gaps between heading, filter bar, and table card |
| 2xl | 48px | Empty state top/bottom padding (`py-12`) |
| 3xl | 64px | — (not used in this phase) |

Exceptions (non-spacing, renderer-level):
- Progress bar height is 8px (`h-2`) — matches the existing ProgressModal convention; not a spacing token.
- Rename inline input height is 32px (`h-8`) — tight height to fit within the table row without disrupting row height.
- Search input inside merge modal is 40px tall (`h-10`) — consistent with existing filter inputs across the platform.
- Modal `max-w-[520px]` (`size="default"`) for rename error display; `size="lg"` (`max-w-[640px]`) for the merge modal (needs room for the search picker list).

## Typography

Declared type ramp: **4 steps — 12 / 14 / 18 / 20px**. Weights: regular (400) + semibold (600).

The existing DataTable body size is `text-[13.5px]` in platform source. For this spec all
body/cell copy is declared at the **14px step** (the nearest ramp value). Executors may
retain `text-[13.5px]` only where they inherit it unmodified from an existing shared
component (`DataTable`, `Modal`) — new code in this phase targets 14px.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Page heading | 20px | 600 (semibold) | 1.2 | "Tags" page heading — matches `AuditLogWidget` h1 |
| Modal title / confirm heading | 18px | 600 (semibold) | 1.2 | `Modal` title prop; Step 2 confirm h3 |
| In-progress counter / body | 14px | 600 (semibold) | 1.4 | Merge progress "processed / total" counter; proceed-button label |
| Body / cell text | 14px | 400 (regular) | 1.5 | Tag label cells, review count, first seen, modal body copy, dropdown items, search input |
| Supporting / meta text | 12px | 400 (regular) | 1.5 | Badge labels, merge-progress sub-text, empty state body, pagination footer, error alerts, column headers |
| Column headers (uppercase) | 12px | 600 (semibold) | 1.4 | `DataTable` `<th>` — uppercase, `tracking-[0.05em]`, `text-subtle` |
| Section labels (uppercase) | 12px | 600 (semibold) | 1.4 | "Merge into" section heading inside merge modal |

Chart axis ticks (recharts SVG, renderer-controlled — cannot use Tailwind classes): **12px**
consistently for both XAxis and YAxis. Legend text: **12px**. These are the only values
outside Tailwind; they stay on the 12px ramp step.

### Surface 2 — Inline Rename

**Activation:** User clicks "Rename" from `TagActionsMenu`. The Label cell for that row switches from read display to an inline input. At most one row can be in rename mode at a time.

**Inline input:**

```
<input
  type="text"
  class="w-full h-8 px-2 py-1 text-[14px] text-ink bg-white border border-line rounded-sm
         focus:outline-none focus:border-yellow focus:ring-1 focus:ring-yellow/40"
  aria-label="Rename tag"
  maxLength={100}
  defaultValue={row.label}
/>
```

Focus is placed on the input immediately on activation.

**Validation (client-side, pre-submit):**
- Empty value (after trim): show inline error below input, block submit.
- Length > 100 chars: disabled by `maxLength`; no additional UI needed.

**Validation (server-side, post-submit):**
- HTTP 400 with `detail` containing "duplicate" → show inline error: "A tag with that name already exists. Use Merge to combine tags."
- Other 400 → show generic inline error: "Could not rename. Please try again."

**Inline error display:**

```
<p role="alert" class="text-[12px] text-red mt-1">{errorMessage}</p>
```

Error appears directly below the input, within the same cell. The cell expands vertically to accommodate it.

**Keyboard interactions:**
- `Enter` → submit rename (same as clicking Save Label)
- `Escape` → cancel rename, restore original label, clear error

**Save / Cancel buttons (appear to the right of the input, inline in the cell):**

```
<button class="ml-2 px-3 py-1 bg-yellow text-black text-[12px] font-semibold rounded-sm
               hover:bg-yellow-hover disabled:opacity-50" aria-label="Save label">
  Save Label
</button>
<button class="ml-2 px-3 py-1 bg-white text-ink border border-line text-[12px] rounded-sm
               hover:bg-line-soft" aria-label="Cancel rename">
  Cancel
</button>
```

**Loading state:** While save is in-flight, the Save Label button shows "Saving…" and is `disabled`. The Cancel button is also `disabled`. Input is `readOnly` during save.

**Success:** Row reverts to read mode with the new label displayed. No toast — the label change is immediately visible in context.

**Rules (from CONTEXT.md D-03/D-04):**
- Save updates ONLY `OrgCanonicalTag.label` (O(1) write). No `ReviewTag` rows touched.
- Title-Case normalization applied server-side; display whatever the server returns.
- ≤3-word cap is NOT enforced for human admin renames. 1–100 chars only.
- NEVER silently merge on duplicate — reject with inline error.

### Surface 3 — Tag Merge Modal

**Trigger:** User clicks "Merge into…" from `TagActionsMenu`. Source tag is the row's tag.

**Modal spec:**
- Size: `lg` (`max-w-[640px]`)
- Title: "Merge tag"
- Subtitle: `"{sourceLabel}"` (the source tag label, in quotes)
- `dismissible={!merging}` (not dismissible while the Celery task is enqueuing)

**Modal body — two-step flow (mirrors `MergeModal.tsx` pattern):**

**Step 1: "pick"** — choose target tag

```
<div class="space-y-4">
  <div>
    <h3 id="merge-target-section"
        class="text-[12px] font-semibold uppercase tracking-[0.05em] text-muted">
      Merge into
    </h3>
    <p class="text-[14px] text-muted mt-1">
      All {N} reviews tagged "{sourceLabel}" will be re-tagged with the target.
      The source tag will be deleted. This cannot be undone.
    </p>
  </div>
  <input
    type="search"
    placeholder="Search tags…"
    class="w-full h-10 px-3 text-[14px] bg-white border border-line rounded-md
           focus:outline-none focus:border-yellow focus:ring-1 focus:ring-yellow/40"
    aria-label="Search tags"
  />
  <div class="max-h-[240px] overflow-y-auto border border-line rounded-md divide-y divide-line-soft">
    {/* Filtered tag options */}
    <label class="flex items-center gap-3 px-3 py-2 cursor-pointer hover:bg-line-soft
                   [&:has(input:checked)]:border-yellow [&:has(input:checked)]:bg-yellow-tint">

```

- Tag list is fetched once on modal open from `GET /api/v1/reviews/canonical-tags/?page_size=200` (all org tags excluding source). Filtered client-side by the search input.
- When search yields no results: show `<p class="text-[14px] text-muted px-3 py-4">No tags match.</p>` inside the scrollable list.
- When loading the tag list: 4-row skeleton inside the scrollable container.

**Step 1 footer buttons:**

```
Cancel  |  [Merge into "{targetLabel}" →]
```

- "Cancel" → `bg-white text-ink border border-line` — closes modal.
- Proceed button is disabled until a target is selected. Label: `Merge into "{targetLabel}" →` once selected, else `Select a target tag` (disabled). Style: `bg-yellow text-black font-semibold`.

**Step 2: "confirm"** — irreversibility warning

Layout mirrors the `MergeModal.tsx` confirm step:

```
<div class="flex items-start gap-4">
  <div class="w-11 h-11 rounded-[12px] bg-red-tint flex items-center justify-center shrink-0">
    <AlertTriangle size={22} class="text-red" aria-hidden="true" />
  </div>
  <div class="flex-1 min-w-0">
    <h3 class="text-[18px] font-semibold text-ink mb-2">Confirm merge</h3>
    <p class="text-[14px] text-muted leading-[1.5]">
      Re-map {N} reviews from "{sourceLabel}" to "{targetLabel}"?
      The source tag will be permanently deleted. This cannot be undone.
    </p>
  </div>
</div>
```

Icon is `red` (not `amber`) to signal irreversibility — this is a destructive action.

**Step 2 footer buttons:**

```
← Back  |  [Confirm merge]
```

- "Confirm merge": `bg-yellow text-black font-semibold`. While submitting: "Starting merge…" + `disabled`.
- On submit: POST to `POST /api/v1/reviews/canonical-tags/{source_id}/merge/` with `{ target_id }`. Server creates the `TagMergeJob`, enqueues the Celery task, returns `{ job_id }`. Modal closes. Merge progress banner appears in-page.

**Error in confirm step:**

```
<div role="alert"
     class="flex items-start gap-2 border-l-4 border-red bg-red-tint text-red rounded-md px-4 py-2 mb-4">
  <AlertCircle size={16} class="mt-1 shrink-0" aria-hidden="true" />
  <span class="text-[12px]">{errorMessage}</span>
</div>
```

Fallback error copy: "Could not start the merge. Please try again."
409 Conflict (another merge in-progress for this org): "A merge is already in progress. Wait for it to complete before starting another."

### Surface 4 — Merge Progress (HTTP-polled)

**Model:** `TagMergeJob` — durable DB record (from CONTEXT.md D-08). Polled via `GET /api/v1/reviews/tag-merge-jobs/active/` which returns the most recent non-dismissed job for the org.

**Poll interval:** 2000ms (2s) while `status === "IN_PROGRESS"` or `status === "PENDING"`. Polling stops when `status === "SUCCESS"` or `status === "FAILED"`.

**In-progress banner:**

The banner is rendered inside the Tags page above the table card (not a modal). It persists across page reloads because it reads from the durable `TagMergeJob` record on mount.

```
<div role="status" aria-live="polite"
     class="rounded-card border border-line bg-white p-4 flex flex-col gap-3">
  <div class="flex items-center justify-between">
    <div class="flex items-center gap-2">
      <Loader2 size={16} class="animate-spin text-muted" aria-hidden="true" />
      <span class="text-[14px] font-semibold text-ink">Merging tags…</span>
    </div>
    <button type="button" aria-label="Dismiss merge progress"
            class="w-7 h-7 rounded-sm text-muted hover:bg-line-soft hover:text-ink
                   flex items-center justify-center"
            onClick={onDismiss}>
      <X size={14} aria-hidden="true" />
    </button>
  </div>
  <div>
    <div class="text-[12px] text-subtle mb-1">
      Re-mapping "{sourceLabel}" → "{targetLabel}" · {processed}/{total} reviews
    </div>
    <div class="w-full h-2 bg-line rounded-full overflow-hidden"
         role="progressbar"
         aria-valuenow={pct}
         aria-valuemin={0}
         aria-valuemax={100}
         aria-label={`Merge progress: ${pct}%`}>
      <div class="h-full bg-yellow rounded-full transition-all" style={{ width: `${pct}%` }} />
    </div>
  </div>
</div>
```

- Bar fill: `bg-yellow` — accent, consistent with the yellow-is-in-progress pattern from ProgressModal.
- `pct = processed / total * 100` when both are non-null; else indeterminate (`w-1/3 animate-pulse` on the fill, omit `aria-valuenow`/`aria-valuemax`).
- Dismiss (`X` button): sets a local `dismissed: true` flag in component state. The job is NOT deleted; if the user navigates away and returns, the banner re-appears if the job is still IN_PROGRESS or PENDING. "Dismiss" only hides it for the current view session.
- Reload survival: on page load, the widget fetches the active job; if status is PENDING/IN_PROGRESS, the banner renders immediately without waiting for the next poll tick.

**PENDING state (task queued, not yet started):**
- Same banner as IN_PROGRESS but with "Queued — waiting to start" sub-label instead of the progress counter.
- `processed/total` may both be null; render indeterminate bar.

**Completion toast:**

When the poll returns `status === "SUCCESS"`:
1. Banner transitions to the hidden state (auto-dismissed).
2. `emitToast({ kind: "success", title: 'Merge complete', body: '"{sourceLabel}" merged into "{targetLabel}".' })` — uses the existing `lib/toast.ts` pattern.
3. The tags table is refetched to reflect the removed source tag and updated target `review_count`.

**Failure path:**

When the poll returns `status === "FAILED"`:
1. Banner changes to failure layout:

```
<div role="alert"
     class="rounded-card border border-red bg-red-tint p-4 flex flex-col gap-3">
  <div class="flex items-start gap-3">
    <AlertCircle size={16} class="text-red mt-1 shrink-0" aria-hidden="true" />
    <div class="flex-1 min-w-0">
      <span class="text-[14px] font-semibold text-red">Merge failed — changes rolled back</span>
      <p class="text-[12px] text-muted mt-1">
        {job.error_message ?? "Something went wrong. The merge was rolled back. No reviews were affected."}
      </p>
    </div>
    <button type="button" aria-label="Dismiss error"
            class="w-7 h-7 rounded-sm text-red hover:bg-red/10 flex items-center justify-center shrink-0">
      <X size={14} aria-hidden="true" />
    </button>
  </div>
</div>
```

2. Dismiss button on the failure banner marks the job as dismissed (`PATCH /api/v1/reviews/tag-merge-jobs/{id}/dismiss/`) so it does not re-appear on reload.

**Polling hook pattern (mirrors `useNotifications`):**

```typescript
// useMergeProgress.ts
useEffect(() => {
  void fetchJob();
  if (status === "PENDING" || status === "IN_PROGRESS") {
    const id = setInterval(() => void fetchJob(), 2_000);
    return () => clearInterval(id);
  }
}, [status]);
```

### Surface 5 — Dashboard Polarity Chart

**Location:** Extension of the existing dashboard. The exact widget to extend is the recharts `BarChart` in `frontend/src/widgets/dashboard/` — most likely a new chart section within `DashboardWidget.tsx` or a new `TagPolarityChart.tsx` sub-component.

**Chart type:** Recharts `BarChart` with `<Bar>` stacking for `mixed` polarity tags — the same library and pattern used by `TopPerformingSection.tsx`.

**Data shape (new API endpoint):**

```typescript
// New type in dashboard/types.ts
export interface TagPolarityBar {
  label: string;              // canonical tag label (truncated to 16 chars for XAxis)
  polarity_type: "always_positive" | "always_negative" | "mixed";
  positive_count: number;     // reviews with ReviewTag.polarity == "positive" for this tag
  negative_count: number;     // reviews with ReviewTag.polarity == "negative" for this tag
  total_count: number;        // = positive_count + negative_count (for always_* tags, one of the two is 0)
}

export interface TagPolarityResponse {
  tags: TagPolarityBar[];     // top 10 by total_count, descending; only canonical_tag IS NOT NULL
  has_more: boolean;          // true if org has >10 canonical tags (for "See all tags" link)
}
```

**Visual contract:**

- One vertical bar per canonical tag on the X-axis.
- `always_positive` tag: single bar, full height = `total_count`, fill `#16A34A` (green).
- `always_negative` tag: single bar, full height = `total_count`, fill `#DC2626` (red).
- `mixed` tag: stacked bar, bottom segment = `positive_count` fill `#16A34A`, top segment = `negative_count` fill `#DC2626`.
- Bar radius: `[4, 4, 0, 0]` (top corners rounded — matches `TopPerformingSection` `Bar` radius).
- Chart height: 240px. `barCategoryGap="35%"`.
- Max 10 tags displayed (ordered by `total_count` desc). If `has_more`, footer link "See all tags →" points to `/admin/org/tags/`.

**Recharts stacked bar implementation:**

```typescript
<BarChart data={tags} barCategoryGap="35%" margin={{ bottom: 48 }}>
  <XAxis
    dataKey="label"
    tick={{ fontSize: 12, fill: "#71717A" }}
    tickFormatter={(name: string) => name.length > 14 ? name.slice(0, 13) + "…" : name}
    angle={-35}
    textAnchor="end"
    height={56}
    axisLine={{ stroke: "#E4E4E7" }}
    tickLine={false}
    interval={0}
  />
  <YAxis
    tick={{ fontSize: 12, fill: "#A1A1AA" }}
    axisLine={false}
    tickLine={false}
    width={28}
  />
  <Tooltip content={<TagPolarityTooltip />} cursor={{ fill: "rgba(0,0,0,0.03)" }} />
  <Legend verticalAlign="top" height={28} iconSize={8} iconType="circle"
          formatter={(value) => <span style={{ fontSize: 12, color: "#71717A" }}>{value}</span>} />
  {/* Stack positive on bottom, negative on top */}
  <Bar dataKey="positive_count" name="Positive" stackId="a" fill="#16A34A" radius={[0,0,0,0]} />
  <Bar dataKey="negative_count" name="Negative" stackId="a" fill="#DC2626" radius={[4,4,0,0]} />
</BarChart>
```

Note: `always_positive` bars will have `negative_count === 0` and `always_negative` bars will have `positive_count === 0` — the stack naturally renders as a single-color bar in those cases.

**Tooltip (`TagPolarityTooltip`):**

```
<div class="bg-white rounded-lg shadow border border-line p-2 text-[14px]">
  <div class="font-semibold text-ink mb-1">{tag.label}</div>
  <div class="text-[12px] text-subtle capitalize mb-1">{polarityLabel}</div>

    <>
```

## Accessibility Contract

### Tags Table
- `<table>` with `aria-label="Canonical tags"` on the wrapping `DataTable`.
- Sort column headers: `aria-sort="ascending" | "descending" | "none"` on the `<th>` for the active sort column.
- Skeleton rows: `aria-busy="true"` (inherited from existing `DataTable` pattern).
- PolarityBadge: color alone does not distinguish polarity — the badge also contains the text label ("Always Positive", "Always Negative", "Mixed").

### Inline Rename
- Input: `aria-label="Rename tag"`.
- Error: `role="alert"` on the error `<p>` so screen readers announce it immediately on appearance.
- Save button: `aria-label="Save label"`. Cancel: `aria-label="Cancel rename"`.

### Merge Modal
- `Modal` component already provides `role="dialog" aria-modal="true" aria-label={title}` and `FocusTrap`.
- Radio group: `role="radiogroup" aria-labelledby="merge-target-section"`.
- Error banner: `role="alert"`.
- "Cannot be undone" warning: also conveyed via the confirm-step layout (AlertTriangle icon + explicit text), not color alone.

### Merge Progress Banner
- `role="status" aria-live="polite"` on in-progress banner — polite so it does not interrupt reading.
- `role="alert"` on failure banner — assertive since it signals something that needs attention.
- Progress bar: `role="progressbar" aria-valuenow aria-valuemin=0 aria-valuemax=100 aria-label="Merge progress: {pct}%"`. When indeterminate: omit `aria-valuenow`/`aria-valuemax`.
- Dismiss button: `aria-label="Dismiss merge progress"` / `"Dismiss error"`.

### Dashboard Polarity Chart
- Chart wrapper: `role="img" aria-label="Tag distribution by polarity bar chart"` (mirrors `TopPerformingSection`).
- Legend uses text labels ("Positive", "Negative"), not color alone.
- Tooltip is mouse/pointer accessible via recharts default; keyboard accessibility is limited by recharts (existing platform precedent — not introduced in this phase).

## State Transition Diagrams

### Inline Rename States

```
idle → [click Rename] → editing
editing → [Escape / Cancel] → idle
editing → [Enter / Save Label, invalid] → editing (with error message)
editing → [Enter / Save Label, in-flight] → saving
saving → [200 OK] → idle (label updated)
saving → [400 duplicate] → editing (with duplicate error)
saving → [other error] → editing (with generic error)
```

### Merge Modal Steps

```
closed → [click "Merge into…"] → open:pick (loading tag list)
open:pick (loading) → [list loaded] → open:pick (interactive)
open:pick → [Escape / Cancel] → closed
open:pick → [select target + click proceed] → open:confirm
open:confirm → [Back] → open:pick
open:confirm → [Confirm merge] → submitting
submitting → [201 Created, job_id returned] → closed + progress banner appears
submitting → [409 Conflict] → open:confirm (with conflict error)
submitting → [other error] → open:confirm (with generic error)
```

### Merge Progress Banner States

```
hidden → [tag-merge-jobs/active/ returns PENDING/IN_PROGRESS] → in-progress
in-progress → [poll: SUCCESS] → hidden (toast emitted, table refetched)
in-progress → [poll: FAILED] → failed
in-progress → [dismiss clicked] → hidden (local session only; job still active)
failed → [dismiss clicked] → hidden (PATCH job as dismissed; won't re-appear on reload)
```
