# Deployment

AWS deployment for the review-master platform. Single EC2 (`t4g.medium`, Graviton) + RDS + Redis (in-container) + ECR, deployed in `ap-south-1` (Mumbai).

Infrastructure is managed by **Terraform** in the sibling workspace folder [`../../review-master-terraform/`](../../review-master-terraform/) (a separate Git repo — see [CLAUDE.md §25](../CLAUDE.md)). The instance itself is provisioned once via Terraform; all app updates go through SSM Run Command (see [`scripts/deploy.sh`](scripts/deploy.sh)) — Terraform never replaces the instance (`ignore_changes = [ami, user_data]`).

**SRE runbooks → [`docs/sre/`](../docs/sre/README.md)**

---

## 1. Goals

- First production deployment for one organisation (~57 stores, 50–60 users).
- Lowest credible monthly cost while remaining a "real" deployment (not a single-container hack).
- Path to scale: known upgrade triggers and known next architecture, no rewrites required.

## 2. Decisions

### 2.1 Compute — single EC2 box running Docker Compose

| | Decision |
|---|---|
| Instance type | **t4g.medium** (2 vCPU, 4 GB, Graviton) |
| OS | Amazon Linux 2023 ARM64 (AMI looked up via `data "aws_ami"`) |
| Disk | 30 GB EBS gp3 root volume, encrypted |
| Region | **ap-south-1** (Mumbai) — closest to customers |
| Backups | RDS automated backups (7-day); EBS snapshot policy not yet configured |
| IP | Elastic IP managed via Terraform (`aws_eip` + `aws_eip_association`) |

The box runs **all six containers** via Docker Compose:

| Container | Purpose |
|---|---|
| `caddy` | Reverse proxy + TLS termination (Let's Encrypt, auto-renew) |
| `web` | Daphne running `config.asgi:application` (HTTP + WebSockets) |
| `worker` | Celery worker — queues `google-sync,ai-enrichment,default`, `--concurrency=2` |
| `beat` | Celery Beat (scheduled tasks). **Exactly one instance — non-negotiable.** |
| `flower` | Celery monitoring UI, bound to `127.0.0.1:5555`, **never published**. SSH-tunnel access only. |
| `redis` | Redis 7 (cache, throttling, sessions, Celery broker/backend, Channels layer) |

Why a single box: the workload is genuinely tiny (60 stores/day, ~5–10 reviews each). ECS Fargate + ALB + ElastiCache would multiply cost ~3× for no functional gain at this scale.

### 2.2 Database — Amazon RDS PostgreSQL

| | Decision |
|---|---|
| Engine | PostgreSQL 16 |
| Instance | db.t4g.micro (Single-AZ, 1 GB RAM) |
| Storage | 20 GB gp3, autoscaling cap **100 GB** |
| Backups | 7-day retention, point-in-time recovery enabled |
| Subnet | RDS subnet group across 2 private subnets (`10.0.10.0/24`, `10.0.11.0/24`) |
| Multi-AZ | **Off** for now (doubles cost). Turn on before second paying customer. |
| Deletion protection | **On**, with final snapshot `review-master-prod-final` |
| Performance Insights | **Enabled** (free 7-day retention tier) |
| Password | Generated by `random_password`, stored at SSM `/review-master/prod/DB_PASSWORD_RAW` (SecureString) with `ignore_changes` so manual rotation is safe |

Why RDS over Postgres-in-Docker: managed backups, point-in-time recovery, and easy upgrade path are worth $14/mo. We never want to lose a customer's data because we forgot to run `pg_dump`.

### 2.3 Networking & TLS

- **VPC:** custom `10.0.0.0/16` with 2 public + 2 private subnets across 2 AZs (see `vpc.tf` in the terraform repo at [`stacks/prod-app/`](../../review-master-terraform/stacks/prod-app/)).
- **Reverse proxy: Caddy** (Let's Encrypt auto-TLS, HTTP/2, gzip, WebSocket out of the box). Decision recorded over nginx because it eliminates certbot + renewal cron — fewer moving parts at this scale.
- **No ALB.** TLS terminates at Caddy on the EC2 box.
- **No ACM** (ACM certs cannot install on EC2 directly; only attach to ALB/CloudFront/API Gateway).
- **Route 53** for DNS. Hosted zone for `reviewbee.in` was migrated from GoDaddy manually and is **referenced via `data "aws_route53_zone"`** — Terraform never creates or destroys the zone. Only the `app.reviewbee.in` A record (→ Elastic IP) is managed by Terraform.
- **SSH access:** **none from the public internet.** All operator access is via AWS Systems Manager Session Manager (`aws ssm start-session`) — the EC2 instance profile has `AmazonSSMManagedInstanceCore` attached. Security groups expose only 80/443 to `0.0.0.0/0`.
- **Security groups:**
  - EC2: 80/443 from `0.0.0.0/0` only.
  - RDS: 5432 from EC2 SG only.

### 2.4 Secrets — AWS Secrets Manager (single JSON blob) + SSM for DB password

> **Changed from the original plan.** The README originally specified SSM Parameter Store SecureString for all secrets ($0/mo). The actual deployment uses **AWS Secrets Manager** for the application env (single JSON secret `review-master/prod`) and SSM SecureString only for the raw DB password. Net cost is ~$0.40/mo for the one secret — accepted in exchange for a single atomic load step on deploy and easier in-console editing of the whole env.

| Where | Name | Contents | Managed by |
|---|---|---|---|
| Secrets Manager | `review-master/prod` | All app env vars as one JSON object (DJANGO_SECRET_KEY, DATABASE_URL, GOOGLE_OAUTH_*, OPENAI_API_KEY, LANGSMITH_*, SENTRY_DSN, RESEND_API_KEY, CADDY_*, S3 settings, etc.) | Terraform creates the secret; values rotated in by hand (`ignore_changes = [secret_string]`) |
| SSM Parameter Store | `/review-master/prod/DB_PASSWORD_RAW` | RDS master password (SecureString) | Terraform via `random_password` |

On deploy, [`scripts/load-secrets.sh`](scripts/load-secrets.sh) fetches the JSON blob from Secrets Manager and writes it to `/etc/review-master.env` for Docker Compose to read.

EC2 instance profile permissions (see `iam.tf` in the terraform repo at [`stacks/prod-app/`](../../review-master-terraform/stacks/prod-app/)):
- `secretsmanager:GetSecretValue` on `arn:aws:secretsmanager:ap-south-1:*:secret:review-master/prod*`
- `AmazonSSMManagedInstanceCore` (covers SSM Session Manager and Parameter Store reads)

### 2.5 Container registry — ECR (private)

- One repo: `review-master/app` (see `ecr.tf` in the terraform repo at [`stacks/prod-app/`](../../review-master-terraform/stacks/prod-app/)).
- Single image, multiple Compose `command:` entries select web/worker/beat/flower behaviour.
- `scan_on_push = true`, AES256 encryption at rest.
- **Lifecycle policy:** untagged images expire after 1 day; keep at most 10 tagged images.
- Pulls from EC2 in same region: free.

### 2.6 CI/CD — GitHub Actions → ECR → EC2

1. **Auth:** GitHub OIDC → IAM role `review-master-github-actions`, trust scoped to `repo:sayone-tech/review-master-v2:ref:refs/heads/main` only (see `iam.tf` in the terraform repo at [`stacks/prod-app/`](../../review-master-terraform/stacks/prod-app/)).
2. **Build:** `docker build` on Actions runner.
3. **Push:** `aws-actions/amazon-ecr-login@v2` → `docker push`.
4. **Deploy:** **SSM Run Command** (`AWS-RunShellScript`) into EC2, restricted by `aws:ResourceTag/Project = review-master`. No SSH from CI. Runs [`scripts/deploy.sh`](scripts/deploy.sh) which does `docker compose pull && docker compose up -d`.
5. **Migrations:** run as a one-off `docker compose run --rm web python manage.py migrate` step before bringing services up.

The GitHub Actions workflow itself lives at `.github/workflows/` (not under `deployment/`). The OIDC role ARN is output by Terraform as `github_oidc_role_arn`.

GitHub Actions cost: $0 (within 2,000 free minutes/month for private repos).

### 2.7 Static & media files — S3

- Bucket: `review-master-static-prod` (see `s3.tf` in the terraform repo at [`stacks/prod-app/`](../../review-master-terraform/stacks/prod-app/)).
- `django-storages` with S3 backend.
- `collectstatic` runs in the Docker build, then static files are uploaded to S3 in a deploy step.
- Bucket policy grants public read on `/static/*` only. CORS allows `GET` from `https://app.reviewbee.in`.
- EC2 instance profile has `s3:PutObject`, `s3:DeleteObject`, `s3:ListBucket` on this bucket so `collectstatic` can run from the box.
- No CloudFront in front of S3 yet — added when traffic justifies it.

### 2.8 Email — Resend (pre-SES)

SES production access is not yet approved. Production currently uses **Resend** via API key (`RESEND_API_KEY` in the Secrets Manager blob, `EMAIL_PROVIDER=resend`). From-address: `noreply@reviewbee.in`, reply-to: `support@reviewbee.in`.

When SES is approved, integration is already specified in `CLAUDE.md` §15 and can be swapped by changing `EMAIL_PROVIDER` and the Django backend.

### 2.9 Observability — CloudWatch + Sentry

- **CloudWatch logs:** Docker `awslogs` log driver ships container stdout/stderr to log group `/review-master/prod` (30-day retention).
- **CloudWatch metrics + agent:** track CPU, memory, disk on EC2; RDS metrics are automatic. RDS Performance Insights enabled.
- **Sentry:** errors from web + worker. Free tier (5k events/mo) is sufficient.
- **Alerts:** SNS topic `review-master-alerts` with email subscription to `renjith@sayonetech.com`. Alarms managed in `cloudwatch.tf` in the terraform repo at [`stacks/prod-app/`](../../review-master-terraform/stacks/prod-app/):
  - EC2 `CPUUtilization` > 70% sustained 10 min
  - EC2 `disk_used_percent` > 80% (requires CloudWatch agent; install via SSM — see file comment)
  - RDS `FreeableMemory` < 100 MB sustained
  - RDS `FreeStorageSpace` < 5 GB
  - RDS `CPUUtilization` > 80% sustained 10 min

### 2.10 Cost guardrails — AWS Budgets

`aws_budgets_budget` named `review-master-monthly` set to **$70/mo** (see `budgets.tf` in the terraform repo at [`stacks/prod-app/`](../../review-master-terraform/stacks/prod-app/)) with two notifications:

- Forecasted > 80% of budget → email
- Actual > 100% of budget → email

The $70 cap leaves ~$25 headroom over the ~$44 estimate for OpenAI, Resend, occasional snapshots, and incidental services.

## 4. Upgrade triggers — when to leave this architecture

| Signal | Next step | Cost delta |
|---|---|---|
| Second paying customer | RDS Multi-AZ | +$12/mo |
| Sustained EC2 CPU > 70% or mem > 85% | EC2 → t4g.large | +$24/mo |
| Daily Celery jobs > 1,000 stores | Move worker to dedicated EC2 OR ECS Fargate | +$10–30/mo |
| Need zero-downtime deploys | Add ALB + second EC2 | +$16/mo + EC2 |
| Compliance / audit requirement | Move secrets to Secrets Manager (rotation) | +$3/mo |

- [ ] CloudWatch alarms armed
- [ ] Sentry project + DSN wired up
- [ ] Backup verification: confirm RDS snapshot exists; confirm restore procedure works on a throwaway

## 7. Resolved decisions

1. **Region:** `ap-south-1` (Mumbai), chosen for customer proximity.
2. **Terraform vs console:** Terraform manages everything (code in the sibling [`review-master-terraform/`](../../review-master-terraform/) repo). The EC2 instance is provisioned once by Terraform but never replaced by it (`ignore_changes = [ami, user_data]`); all app updates go through SSM Run Command.
3. **Domain registrar:** `reviewbee.in` was migrated from GoDaddy to Route 53 manually. Terraform references the hosted zone via `data "aws_route53_zone"` — it never creates or destroys the zone, only the `app.reviewbee.in` A record.
4. **Email provider during SES sandbox:** Resend (API key in Secrets Manager).
5. **Static asset CDN:** shipped without CloudFront. Revisit if static asset latency hurts UX.

## 8. Terraform state — known limitation

State currently lives **locally** on the operator's laptop at `review-master-terraform/terraform.tfstate`. The S3 backend block in `main.tf` is commented out as a TODO. The file is `.gitignore`d in the sibling repo and has never been committed. Because it contains the generated DB password and references to Secrets Manager secrets, **keep the file out of cloud backups (iCloud, Dropbox, etc.)**. Migrate to the S3 backend (`bucket = "review-master-tfstate"`, encrypted) before any teammate works on infra.
